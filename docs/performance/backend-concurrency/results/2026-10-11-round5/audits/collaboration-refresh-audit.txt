Round 5 collaboration refresh audit (baseline df3e6f04)

Ownership and true triggers
- Ordinary root chat: Renderer handles interactive display and legacy chat persistence; Core owns Trace/action/guidance durable facts. This change removes no save/writeback. Any later removal is separately gated on Core checkpoint/history reconstruction proof.
- Child observer: useObserverConversation is read-only. Exact root-agent/root-conversation/agent/conversation scope authorizes each recent/older page; process-local observer envelopes and command events supply live overlays. A completed full replay is cached in memory only. Reopening recovers from authorized Core snapshot/history/liveStream cursor. This change retains messageLimit=40, 32ms history yield, live-journal limit512, 75ms visible refresh delay, exact delta cursors and error/retry.
- Collaboration store: authoritative tree + contiguous durable event replay; recovery checkpoint is in-memory and requires Host identity reauthorization. Cache bound4, idleTTL5min unchanged. Ordinary token/message_delta events cause no tree or approval RPC. Agent guidance_applied only supplies ephemeral transmission metadata.
- Projected approval: list reads Core pending actions; decision RPC targets durable approvalId. Only nonpending decision acknowledgements prevent stale pending list regression. No Renderer save path. SQL approval_projected/approval_updated triggers cover child pending status/target_status/updated_at mutations. Full hydrationRevision also invalidates approval read so reconnect with unchanged sequence still repairs transport gaps.
- Organization workflow monitor, activity, execution hooks already have bounded pending+dirty and scoped durable triggers. Runtime notification directly accepts snapshot without RPC; monitoring progress refresh waits1s, poll/recovery5s. No workflow changes were justified. WorkflowActivity still conservatively refreshes on unscoped started/done/nonrecoverable error when no exact owner identity is supplied; do not claim all workflow invalidation is root-exact.

Implementation
- Shared TrailingRefresh: one active read, one replaceable trailing read; callers share trailing completion, failures remain observable, no per-event task list. Queues are scoped; navigation does not wait for the previous root/child.
- Approvals keep latest-generation stale suppression and durable ACK overlay; external durable invalidations coalesce while waiting.
- Observer entire recent/history read chain is serialized; superseded load stops after its already-issued page returns. Latest window retains complete live journal and applies exact unseen cursor suffix. Root changes retain independent authorization.
- CollaborationStore hydrate and catchUp now share one physical read lane. Full recovery dominates checkpoint resume; new recovery invalidates publication immediately, then waits for existing read before issuing a replacement. Pause/destroy fence old reads and clear pending work. Durable cursors/gap recovery/error behavior preserved.
- AppShell approval invalidation uses hydrationRevision:approvalInvalidationSequence, not every root tree sequence.
