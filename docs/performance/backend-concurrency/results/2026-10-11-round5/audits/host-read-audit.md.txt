# 第五轮 Host 窄读取与展示恢复审计

本记录覆盖 transport 代理负责的第五轮修改，待 root 统一归档。使用合成数据和临时隔离数据库；没有真实模型调用、外发消息或真实用户库。生产 Rust 由 root 统一构建；本代理未运行 Cargo、提交或 push。

## 链路与证据范围

第一轮/第四轮矩阵的计时边界是 Core Server 入口到回执，不包含真实 Electron Host 管道，因此不能据此证明 Host JSON-RPC 是首要瓶颈。本次源码审计也没有发现必须扩大传输队列、添加缓存或并行大响应的独立证据。

`QueuedConversationReads` 原有逻辑保留：全量 `loadConversation`、`loadConversations` 和 observer history 同时至多一个活动读取；仅尚未开始的相同请求合并，活动读取期间的新请求形成新尾随快照；高优先 observer 最多连续超越四次。`jsonRpcClient.ts` 和 `queuedConversationReads.ts` 均无修改。

原 Host 内部 `ReadToolFileSource.resolveReadToolFile` 为打开一个读取结果文件，调用 `loadConversation`、跨进程接收全部消息，然后解析选中 assistant 的整个 `agentRunJson`。这条路径只需要 conversation/project、assistant/run、精确 call、typed identity 和结果路径。其他全历史读取用于用户显示、仍走原队列。

新增 `storage.loadReadToolFileContext({ conversationId, assistantMessageId, callId })` 是一对一替换，单次仍为 **一个 RPC**，不宣称减少 RPC 数。改进来自返回和解析内容减少，以及不必排在 Host 其他全历史响应后。Core 仍需要投影选中 Run 的 Trace，不能宣称消除了全部 Trace 投影 CPU。

## 所有权、顺序和兼容

- Core 用一个读取事务获取 conversation metadata、选中 assistant 消息、同范围 Trace/Guidance/工具证据；所有字段来自同一个 SQLite 快照。没有缓存，没有两个快照拼接。
- server 沿用全历史读取的 `authorize_user_conversation_write` 授权入口，并使用与 `storage.loadConversation` 相同的 Conversation 资源范围和 Read lane；已知同范围写/读顺序保持，未知仍保守。
- Core 只返回一个 call 的字符串字段，省略消息正文、其他消息、其他工具和通用结果正文。身份字段缺失与显式损坏/null 严格区分：legacy 缺失仍兼容，损坏显式身份仍由 Host 拒绝。
- Core 复用原 history projection 的 Trace 优先及 legacy 合并规则，同时应用原 active/root/workflow 消息可见性过滤。Renderer 不再保存 run JSON 时，已有 Trace 仍能提供读取证明。
- Host 保留 conversation/project/assistant 精确匹配、同 run 或精确 observer live proof、builtin identity、精确 path 比较、附件归属及 frozen workspace/path 最终校验。响应本身不授予文件访问权限。
- 没有消息时仍允许原有精确 live observer fallback；删除后的新查询返回 null。旧 pinned read 可以读到删除前的完整快照，不能拼接删除后 metadata。

## Trace 截断与展示恢复补充

Trace 是有界历史；单靠它不能恢复原展示全部网页来源、完整摘要输入或读取缩略图。`runtime_checkpoint_web_read` 只接收 RendererSafeAgentEvent，ToolCall 必须有严格 builtin/toolName 身份，结果必须匹配已有可信 call。

保存的内容是现有 web/read 展示算法消费的白名单输入；网页保留完整 sources/answer/content，避免重新实现 `webFetchPresentation.ts` 的 Markdown AST 算法。读取活动精确保留 path、文件名、类型、状态、mime、错误和现有 512 KiB 以内合法缩略图；不保存完整图像或读取正文。`ReadToolActivity` 额外使用的目录错误 code 和生成图 artifact receipt 已保留。完整文件仍通过原授权路径按需打开。

`fullDataUrl` 在原 `activityFromResult` 中恒为 undefined，原 normalize 也移除 image fullDataUrl；这次不持久化它没有降低原恢复行为。

Core history 对带 Core checkpoint 的 web/read 内容再核对精确 Trace builtin call/result，approvalStatus 来自 Trace。未提交结果不恢复为 completed。Trace 原有 metadata 作为基础，再叠加完整展示字段；不会因较窄 checkpoint 丢掉 Trace 的正常 metadata。数据库补丁按 id 合并、Core provenance 恢复证明和 Runtime 集成由 root/access 负责；Renderer 所有状态的活动重建由 preparing 负责。

FileChange 审批 API 在 Runtime emitter 外结算，因此另外加入同快照恢复 overlay：一次查询公开 metadata，绑定 conversation/assistant/run/原 builtin apply_patch call，按 transactionId 更新状态/统计。不会读取 draft/base 正文、修改执行或授予权限。每条消息只解析/编码一次 run JSON。Skill installation overlay 由 preparing 实现，本代理负责 history 接线。
