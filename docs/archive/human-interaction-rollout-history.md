# 人机交互分轮交付历史

> 本文归档 2026-09-05 至 2026-09-14 期间的人机交互分轮实施记录。它保留演进背景，不定义当前 Tool、协议、数据库、测试数量或发布行为。请以[当前人机交互 Tool 契约](../subsystems/human-interaction.md)和代码为准。

## 为什么归档

最初的实现文档把当前行为、每轮范围、当时的 schema 基线和测试统计写在同一篇页面中。随着阻塞与非阻塞路径均上线，这种写法容易把“第 N 轮完成时的局部事实”误读为当前契约。

现将完成的交付路线保留在本页，使当前子系统文档只回答：

- 何时选用阻塞或非阻塞 Tool；
- 数据、恢复、投递和安全边界如何工作；
- 修改后应检查哪些跨层不变量。

## 五轮实施路线

| 轮次 | 当时交付内容                                               | 历史结果                                                    |
| ---- | ---------------------------------------------------------- | ----------------------------------------------------------- |
| 1    | 共享协议、独立设置、SQLite 事实表、Host API 与动态能力外壳 | 先建立可验证的领域所有权；不提前向真实模型暴露不可执行 Tool |
| 2    | 阻塞 Tool、运行暂停、原调用恢复、停止与重启围栏            | 同步回答只恢复原 ToolCall，不另建普通用户消息               |
| 3    | 非阻塞 Tool、多个待答批次、回答投递、空闲续接与忽略        | 异步接纳立即返回；回答随后经引导或新根 Turn 投递            |
| 4    | 设置页、分页面板、审批抢占、最小化与聊天气泡               | Renderer 只管理展示草稿，Host 继续拥有状态与执行权          |
| 5    | 跨层验收、竞态修复、协议和用户文档                         | 完成真实 Host/Preload/Core Server/UI 链路验证               |

### 第 1 轮：先建立领域边界

第一轮把人机交互设计为 Host-owned 的持久事实，而不是 Renderer 对话框或模型的临时输出。核心决定包括：

- 模型输入只描述问题和建议选项；Host 生成批次、问题和选项 ID，并验证 Conversation、Run 和 ToolCall 归属。
- 设置独立于 Prompt Preferences 保存，并以 revision/CAS 更新；创建问题和关闭设置在同一事务边界裁定先后。
- Request、Response、Delivery、Suspension 等事实被拆开，以免 UI 的“已提交”误被当作模型已经消费。
- 根 Agent、子 Agent 和 Automation 从一开始分离。子 Agent 不能借助历史快照或 Renderer RPC 获得向用户提问的权限。
- 运行时未就绪时不暴露 schema 或专项提示，避免模型调用无执行入口的 Tool。

### 第 2 轮：阻塞同步工具

第二轮的重点是把“等待用户”接入真实 Agent Loop，而不是让前端自行续跑：

- Runtime 收到同步调用后冻结 checkpoint、已完成 Tool、后续队列、Provider continuation 和上下文。
- Host 与问题批次一起保存私有恢复材料和累计用量，随后释放 worker，但保留逻辑 Run 的 Conversation 占用。
- 用户整批回答只生成原 ToolCall 的一次成功结果，随后从暂停点继续；它不能同时作为普通用户消息进入模型。
- Stop、重启、连续同步提问和审批交接都需要持久的 claim/执行围栏。无法判断副作用是否发生时宁可失败，也不自动重放。

### 第 3 轮：异步工具与回答投递

第三轮将“问题已记录”和“用户回答已送达”拆开：

- 异步调用只有 Host 已原子接纳后才返回 accepted 事实；当前 Run 继续完成独立工作。
- 回答提交后先成为不可变 Response 和 pending Delivery；活跃 Run 使用既有引导队列，空闲 Conversation 通过正常根 Turn 入口继续。
- 忽略仅结算指定异步批次，不生成普通用户消息、引导或 Wake。其最小状态事实在后续自然采样或恢复对账中被观察。
- 运行占用、审批、同步等待、压缩和停止被看作投递路径的仲裁条件，而不是前端可以绕过的提示。

### 第 4 轮：跨进程 UI

第四轮将持久状态接到 Renderer：

- 设置、请求列表、提交和忽略通过独立 Host API 传递；notification 是失效提示，完整查询结果才是权威状态。
- 一个 Tool 调用对应一个批次。用户逐题填写、暂存草稿并整批提交；异步批次可最小化后从时间线入口恢复。
- 审批优先于阻塞问题，阻塞问题优先于非阻塞问题。抢占不应丢失未提交草稿。
- 问题与回答以一个问答气泡渲染，但展示层不能伪造模型可消费的回答或直接启动 Run。

### 第 5 轮：验收与修复

最后一轮将测试范围扩展到协议、持久化、运行时、Core Server、IPC、Preload、Renderer 和真实跨进程浏览器场景。历史测试特别针对：

- 同步 ToolResult 唯一性、暂停恢复顺序、停止和重启；
- 多个异步批次、运行中引导、空闲续接、忽略和投递去重；
- 设置变更、根/子 Agent/Automation 边界、通知乱序和 UI 草稿；
- 结果未知时不自动重放可能收费或有副作用的模型/Tool 调用。

这些测试名称、用例数量和当时的 schema 值是开发快照，不应作为当前发布门禁或兼容承诺。

## 交付后仍影响理解的修订

| 日期       | 修订                                              | 保留的设计结论                                                        |
| ---------- | ------------------------------------------------- | --------------------------------------------------------------------- |
| 2026-09-06 | 忽略状态改为普通历史投影；能力状态跨 Run 续存     | 忽略不会额外唤醒模型；动态能力的缺失原因仍可被模型看见                |
| 2026-09-08 | 审批期间保留已接纳的异步引导                      | 审批接力不能把已接纳的人类回答替换、丢弃或重复投递                    |
| 2026-09-14 | 空闲异步回答的新根 Turn 接入当前账户/许可访问检查 | 新的用户意图不能绕过实时登录、许可和 Host admission；拒绝前不写入回答 |

这些修订的当前行为已折叠进[当前契约](../subsystems/human-interaction.md)，不需要回到本页拼接规范。

## 历史验证的边界

实施期间的定向 Rust、TypeScript、Renderer 和跨进程测试均使用可控 Provider、临时 SQLite 或测试 IPC；它们验证协议、状态机和恢复边界，不代表商业模型质量评估、生产 Provider 压力结果或第三方服务可用性。

历史记录中出现的旧 checkpoint、Trace、storage schema 或 reset 基线不能用于恢复新数据。仓库的开发库处理策略、当前 schema、签名发布和正式回归门禁须阅读相应的 current 文档。
