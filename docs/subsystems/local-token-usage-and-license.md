# 本机 Token 活动与账号许可

## 边界

Token 活动属于本机，不属于账号，不跨设备同步。账号退出、切换以及聊天/计费记录清理不修改独立统计。没有 Token HTTP API、上传队列、遥测或设备注册。已有云端账号、资料和头像功能不变。许可不阻断登录和进入应用，管理普通聊天、编辑重新生成、空闲后的异步追问答案和自动化启动新回合的准入，不取消正在执行的任务、审批、工具、子任务、自动化运行或 Core Server。

## 本机统计

Rust Core 在模型请求 observation 持久化事务中按唯一请求 ID 幂等提取实际用量，覆盖常规模型请求与手动/自动压缩。按完成时间的 Asia/Shanghai 日期记录，不按整个 run 的累计 Done 快照相加。输入缓存使用现有规范化输入，思考输出不重复加；缺少完整实际用量的请求只计入“未报告用量”，不从文本或估算 Token 补数。

schema v47 包含本机统计表，空库直接创建 v47，已有精确 v47 库只校验、不重建。2026-09-14 经用户确认，开发期移除 v46 → v47 自动升级；所有旧版库（包括 v46）均返回 `development_storage_schema_reset_required`，不修改原库，需由开发者另行确认后执行显式重建。统计开始时间之前的旧 observation 不回填。查询 RPC 为 `agent.getLocalTokenUsage`，仅走本地 Core Server/IPC，日期范围最多 3660 天，计数以十进制字符串跨 IPC 传输以避免精度损失。

个人资料展示今日/累计/单日最高、所选年份合计及年度热力图，不展示下方日/周/累计趋势和说明段落。年份通过左右按钮切换，最小 2026，最大当前上海年份。刷新仅重新读取本机统计，保留已显示数据、热力图节点及页面滚动位置，不触发资料或许可刷新；切年读取成功后再同时更新年份与数据，失败仍保留原图。本机计数不是计费或防篡改证据；服务商未返回、进程崩溃前未落盘的用量无法从客户端凭空恢复。

## 许可

`LicenseService` 在 Main 订阅账号状态，使用现有登录令牌请求 `GET /v1/me/license`。Main-only `AuthService.getAccessToken` 不暴露给 preload。`LicenseState` 只含许可状态、日期和安全错误码。受信 IPC 提供 `getState`、`refresh`、`openManagement`、`onStateChanged`。

云端固定 SKU 为 `captain-who-desktop`，明确授予的默认许可为 active、无到期日。缺记录或接口错误绝不推断为允许。正向结果截止时间不得超过服务端验证时间后 24 小时，且不得超过实际许可到期日。桌面将这段有效时长映射到本机接收时间，并将请求延迟计入时长；进程内使用单调时钟限制。观察到过期或回退到接收之前的本地时钟时立即清除内存许可，随后校正时钟也不能离线恢复旧许可。

2026-09-14 经用户批准，许可仅保留在当前进程内。每次冷启动、退出后重新登录或切换账号，都必须重新通过已有 `GET /v1/me/license` 在线核验；同一天重启会增加一次请求，但不会增加五分钟许可轮询。移除了磁盘许可缓存读写代码，旧版 `account-license.enc` 及其 `.tmp` 不再读取，也不自动删除用户已有文件；打包隐私扫描继续拒绝这些历史文件。备份还原旧许可文件、修改其中的 receivedAt 或通过重启重置单调时钟，都不能产生本进程的放行资格。账号登录会话仍由独立的 SessionStore 安全保存，不要求每次手输密码。

有效许可安排截止时间的一次性复查，不使用五分钟许可轮询。失败按 1 分钟起步指数退避，上限 1 小时；明确拒绝最多每小时自动复查，用户可主动重试（错误/拒绝后的短期退避仍有效）。缓存有效时的网络失败不撤销该缓存；缓存到期且无法联网时只阻止新的用户回合。云端提前撤销的传播最多可延迟 24 小时。

资料刷新使用 `/v1/me?includeEntitlements=false`，跳过许可查询；现有账号有效性复查不因此放宽。退出清空内存准入并取消在途许可请求，迟到响应不能为另一账号授予许可。已有工作区不因许可状态变化被卸载或蒙住。新回合和 rewrite 在 Main 检查账号与许可，Core Server 的真正新 root Turn 原子准入再次验证有界执行 lease，包括任务结束后才收到的异步答案。活跃回合的 steer、既有回合恢复和子任务不因此重新申请新回合许可。

### 引导、草稿和官网返回

主动发送/重写/立即运行时，未登录复用登录页；已登录且明确无许可打开系统浏览器的固定 `https://captainwhoagent.com/account`，不拼接访问令牌。正在验证或网络失败只提示验证/重试，不当作无许可跳转。`LicenseManagementService` 合并在途打开请求并限制 10 秒内重复打开；确实离开后返回应用时，针对同一账号的一次访问触发一次许可重验（访问最多保留 10 分钟，重验间隔至少 30 秒）。普通窗口聚焦不因此查询许可。此管理返回允许跳过旧的失败退避，避免已在官网处理后还要等一天；不自动重发被拦截的内容。

明确准入拒绝保留草稿/队列，暂停队列自动发送，用户恢复权限后主动继续。不把普通 IPC/网络不确定错误等同于“服务端尚未执行”。稳定拒绝码为 `ACCOUNT_LOGIN_REQUIRED`、`ACCOUNT_LICENSE_REQUIRED`、`ACCOUNT_LICENSE_UNAVAILABLE`。

### Core Server 新回合及自动化后台准入

Main 通过私有 `core.setExecutionAccess` 同步不含身份明文或凭据的内存快照：revision、identityEpoch、reason、issuedAt、validUntil。Core Server 默认拒绝未同步状态，使用代次、顺序及本机时限拒绝迟到或过期的授权。快照最多 60 秒，并受 Main 实际许可剩余时间截断；Main 每 30 秒、账号/许可变化时以及 Core Server 启动时同步。**这只是本机 IPC 的短租约续传，不是每 30 秒查询云端**，不会延长 24 小时云端许可缓存。停止的 Core Server 不会被同步器重启，Core Server 不接触账号令牌、不自行访问 CloudBase。

计划触发与“立即运行”都必须在 Core Server 创建新回合消息和 Trace 的原子准入前验证；不能仅依赖 Main 的立即运行按钮检查。失权时只把尚未实际准入的本次运行结算为既有 Failed 终态及上述安全原因码，在界面解释为“未执行”。不阻塞整条计划，不使用短周期 defer 重试，不在恢复后补跑；计划继续保留，下个正常时间按当时权限执行。运行中/等待审批的观察恢复不受此新准入检查影响。没有为此新增本地表或云端字段。

## 验证与上线顺序

核心自动化覆盖请求去重、归日、空库创建/当前 schema 重开、旧版 schema 拒绝且不改原库、删除不减统计、进程内许可缓存 24 小时/真实到期、离线、冷启动必须联网、账号切换及迟到响应。安全回归包括 30 次模拟回拨重启均不恢复旧许可、单调时钟到期及观察到回拨后禁止复活旧许可。Browser 测试覆盖本机活动和启动/运行中的许可边界。

此方案解决磁盘许可回放与正常程序路径的漏检，不把它描述为设备所有者无法破解的 DRM。Core Server 的本地执行 lease 仍信任 Main，并非服务端签名凭证；掌控并修改整个程序的本机管理员仍在信任边界之外。若未来要求抵抗独立启动/改造 Core Server，需要另行引入服务端签名 lease、Core Server 公钥验签及配套发行/密钥轮换流程。

node --test scripts/verify-packaged-privacy.test.mjs
pnpm build

云端实施代码及迁移在网站仓库 `cloudbase/docs/DESKTOP_LICENSE.md` 中说明。云端迁移 013 和新 API 必须先经测试环境验收、批准并上线，随后才启用要求许可的桌面版本。旧云端没有该接口时，桌面应显示待验证，不使用本地“默认允许”绕过。代码、本地模拟测试不代表云端已部署；真实登录、实际系统安全存储和完整任务的人工验收仍需分别记录。不自动生成 DMG。

### 2026-09-13 云端上线记录

已获用户批准，按测试环境、正式环境的顺序完成迁移 013 和 Account API code-only 部署。测试环境只额外补齐许可表的停用账号读取限制及配套只读函数，未扩展到其他表或业务 RPC。测试环境的 2 个、正式环境的 3 个现有正常账号已获得明确的长期许可；缺少初始化许可的正常账号均为 0。

两个环境均通过独立回滚事务验收：新资料自动授权、账号读取隔离、停用账号拒绝、普通用户写入和管理员 RPC 拒绝。临时测试资料及许可全部回滚，没有创建 CloudBase Auth 身份。正式 API 最终健康/数据库就绪检查均为 HTTP 200；未认证的许可请求为 HTTP 401 且禁止缓存。上述检查不等同于真实账号已登录后成功获得 HTTP 200 许可。

完整源代码版本、云端请求编号、部署前恢复点和未验收项记录在网站仓库的许可部署文档中。未更改云端凭据、环境变量或启用管理员写入；未增加 Token 上传。桌面构建和相关回归测试通过，真实账号端到端验收仍待账号持有人完成。

### 桌面人工验收

云端上线后，在最新开发版中由账号持有人自行登录，不向开发者提供密码、验证码或访问令牌：

1. 检查个人资料、头像和许可状态；已明确授予且没有到期日的许可应显示“长期有效”。
2. 完成一轮确实返回实际用量的模型请求，再刷新本机 Token 活动；当天和累计数量增加，原有聊天和模型配置保留。
3. 运行任务时退出登录：任务继续，不能启动新用户回合；重新登录后可继续使用，本机 Token 数不因账号变化而重置。
4. 重启开发版，确认本机统计和已保存登录会话保留，许可必须重新联网验证；未取得新的允许结果前不能发起新回合。真实有限到期与撤销的线上试验仅使用专用测试账号，不修改日常账号许可来验收。

自动化测试和隔离 Electron 启动测试不能替代上述真实账号验收。现有安装包不随源码或云端部署自动更新。
