# 工作流定义与画布编辑

当前实现是工作流第一阶段：设置中的定义管理、画布编辑、校验和本地持久化。保存图不创建 Agent、Wake 或执行授权，不向模型上下文注册工作流。执行调度、能力开关、渐进披露、启动工具、右侧运行分组和 Create Workflow 技能属于后续阶段。

## 编辑入口

设置 → 工作流，与子 Agent 页面同级。列表中的新建、编辑进入原生编辑页面。「基本信息」填写名称、简介和公共背景，空字段显示简短填写提示；「流程设计」使用页面内画布，两页共享同一份草稿。顶部「保存工作流」一次保存完整定义，保存后保持编辑；有未保存修改时离开页面需确认，保存期间阻止离开。

画布的「添加节点」菜单支持搜索模板和新建空白节点，可点击添加或拖入指定位置。节点右侧的配置按钮是节点配置面板的唯一入口；点击、聚焦、拖动或新建节点只选中节点。节点任务与流转规则分开显示，公共背景只在基本信息页编辑，不在节点面板重复展示。模板选择器采用应用内样式，名称和模型分两行显示。

画布默认显示两个可拖动的根 Agent 节点，分别承接输入和输出。它们是工作流边界的图形入口，不能作为工作节点删除或配置，也不计入执行节点数量。端口支持直接拖拽和点击连接，也提供连线表单；所有入口流共用根 Agent 输入端，所有出口流共用输出端。画布支持滚动、空格拖动、缩放和适应视图，回边和自环单独绕行。

连线使用带圆角的正交路由，按实际线段检测节点障碍，优先选择局部短路径，并为分叉和汇合对齐公共通道；横向间距较小不会被视为回流。发生阻挡时比较附近的上下通道，复杂遮挡使用带转弯成本的网格搜索。根节点同样参与避让，重复连线分配独立路径，拖动节点时重新计算。该布局只影响连线显示，不移动用户放置的节点，也不改变工作流的连接关系。

两条连线的直线段内部发生交叉时，竖线使用小圆弧跨过横线，并以画布背景描边分隔上下层。共享通道、分叉汇合点和圆角处不生成跨线桥；桥随缩放和选中状态显示，不改变流向或连接关系。

基本信息和图内容共享撤销/重做历史，删除节点同时记录其连线及规则引用，同一次拖动归为一步。平移和缩放只更新视口，不影响未保存标记或占用撤销步骤；点击保存时会一并持久化当前视口。

可以拖入已有子 Agent 模板，也可以创建不绑定模板的空白节点。两者使用同一 Node 结构。模板引用可空；引用删除后仍保留定义，并产生可修复的草稿问题。公共背景只有一个值，所有节点共享；节点分别存储接收说明、任务说明和交付说明。坐标和视口属于布局，不决定执行顺序。

空白节点通过 `modelConfigId` 选择模型；绑定模板的节点只引用 `templateId`，模型固定采用模板配置，不能额外覆盖。模板选择项和画布节点的第二行展示模型名称。可选模型复用系统的权威可用性投影，已保存模型失效时保留原引用并允许重新选择，不静默切换。旧 v1 定义缺少 `modelConfigId` 时按 null 读取，仍可打开编辑；未选择模型的空白节点保存为草稿。

## 图与规则

`schemaVersion: 1` 定义包含工作流基本信息、nodes、flows、boundaryPositions 和 viewport。`boundaryPositions` 保存根 Agent 输入、输出节点的坐标，参与保存与撤销；旧定义未提供时，根据原图布局生成默认位置。Flow 两端各自是 `boundary` 或带稳定 `nodeId` 的 `node`，不能两端都是 boundary：

- boundary → node：根 Agent 提供的入口流。
- node → node：内部依赖，允许回边和自环。
- node → boundary：返回根 Agent 的出口流。

节点 ID 独立于模板 ID，同一模板可以引用多次。入流和出流分别持有 Rule：

| mode   | 定义                                             |
| ------ | ------------------------------------------------ |
| all    | 全部流参与                                       |
| one    | 恰好一条                                         |
| any    | 至少一条                                         |
| range  | min 至 max 条                                    |
| custom | required 必选，groups 指定各组 min/max，其余可选 |

同一侧的必选项和分组互不重叠，组内流不重复；这样无需求解任意布尔表达式即可验证数量规则。切换模式后只对当前模式执行语义校验。全可选且没有正数最低输入/输出要求的 custom 规则标记为草稿问题。第一阶段只校验定义，不承诺这些规则已执行。

## 权威校验与保存

`agent.workflows.request` 是设置页面的 Host RPC，不是模型工具。操作为 list、validate、save、delete。Electron 对请求/结果做严格字段解析，Rust 再执行结构和语义校验。编辑期间不发送 validate 请求，也不显示实时校验面板。点击「保存工作流」时只发送 save 请求，使用后端随保存返回的校验结果；若存在问题，保存为草稿并通过标准弹窗显示该次保存的问题，点击「知道了」关闭，列表不保留问题面板。前端不维护另一套图有效性算法。

结构损坏（不支持的版本、重复 ID、指向不存在节点的连线、无效坐标、超限数据）拒绝保存；名称/任务缺失、模板缺失、缺少入口/出口、不可达节点、没有出口路径、规则矛盾允许保存为草稿并返回 issues。每份图最多 128 节点、512 连线，序列化定义最多 2 MB，最多保存 1,000 份定义，定义目录总 JSON 大小不超过 16 MiB。

定义位于 SQLite `workflow_definitions`，通过 revision 乐观并发控制。新建 expectedRevision 为 0，更新和删除需匹配已保存 revision，冲突不覆盖新内容。模板可用性与图验证在事务内读取；列表重新计算 issues，模板删除不会静默改变工作流。v53→v54 只增加定义表和索引，保留既有历史。

## 后续运行时边界

Definition 与未来 Run 分离。后续运行应冻结定义/模板/权限，记录节点执行实例和真实 Agent/Wake/Run 绑定，避免将循环轮次混入静态图。工作流不改变现有 Agent 树的组织含义，连线不授予通信或工具权限。
