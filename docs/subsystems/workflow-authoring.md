# 工作流定义与画布编辑

当前实现包括设置中的模板管理、画布编辑、校验，以及独立工作流实例的对话绑定和本地持久化。左侧「已安排」下方的「工作流」进入全局管理，工作流不隶属于项目，绑定的对话允许跨项目。保存模板不创建对话；确认实例绑定时才为未填补的智能体节点创建空对话。已接入工作流 World State、专用消息工具、持久逻辑门输入、独立对话投递和用户节点完成确认。

本文核验范围包括当前工作树中的实例启停、归档保护和只读流程图实现；这些是开发现状，不表示已随公开版本发布。Workflow definition schema v1 与 SQLite schema 版本独立，迁移真源见[存储与数据生命周期](../architecture/storage-and-data-lifecycle.md)。

## 编辑入口

设置 → 工作流模板，与子 Agent 页面同级。列表中的新建、编辑进入原生编辑页面。「基本信息」填写名称、简介和公共背景，空字段显示简短填写提示；「流程设计」使用页面内画布，两页共享同一份草稿。顶栏紧凑展示工作流名称、基本信息/流程设计切换和保存；流程设计工具栏保持单行，左侧的添加节点、连线、拖动以及右侧配置、删除均为统一 16px 图标按钮，悬停/聚焦时用圆角提示解释功能；右侧在选中连线时平铺名称、起点、终点；选中 Agent 时显示头像、名称、权限、模型选择与「配置」入口。Agent、逻辑门、流股统一在最右侧使用同款垃圾桶删除按钮；配置面板底部不重复放置删除入口。顶部「保存工作流模板」一次保存完整定义，保存后保持编辑；有未保存修改时离开页面需确认，保存期间阻止离开。

画布的「添加节点」菜单提供智能体、用户、输入逻辑门和输出逻辑门，可点击添加或拖入指定位置。双击节点或聚焦后按 Enter 打开详细配置；Agent 也可通过顶部「配置」打开。单击、聚焦、拖动或新建节点只选中节点，Agent 的名称、权限和模型在顶部即时编辑；Agent 详细面板配置任务与输入、输出说明；逻辑门有独立的规则配置面板，公共背景只在基本信息页编辑，不在节点面板重复展示。权限与模型选择器采用应用内样式。配置页不提供连接根节点的快捷按钮，用户入口通过画布连线模式连接。

画布默认只显示一个可拖动的用户输入入口，使用当前用户的头像和用户名。入口只允许向外连接，不能删除或配置，也不计入执行节点数量。没有固定出口；任何智能体或用户节点都可以结束一条分支。「连线」进入持续连线模式：依次点击两个节点连接，鼠标点击位置只负责选中端点；系统根据节点相对位置自动选边和分配接线点，不再弹出连线表单。右侧手形按钮恢复选择/拖动，并取消待连接预览，Escape 先取消预览、再次按下退出连线模式。所有入口流共用用户输入端，用户还可添加普通用户节点来参与后续步骤。Agent 卡片使用紧凑的高对比填充（深色主题浅底深字，浅色主题深底浅字），复用内置头像库按节点 ID 稳定分配头像，重命名、拖动、保存后重新打开不改变头像。画布支持滚动、空格拖动、缩放和适应视图，回边单独绕行。每条流分别保存可选的 sourceAnchor/targetAnchor（side + 0–1 相对 offset），圆点可沿合法边框拖动；落点随节点移动，支持撤销/重做和保存恢复。普通卡片四边可选，输入门在左侧底边接收、右侧尖端输出，输出门左侧尖端接收、右侧底边输出。门尖固定、底边滑动，斜边不接线。省略落点表示自动布局：普通节点优先选择相向边，逻辑门底边按对端位置排序并留出间距。显式落点表示手动固定，自动分配会避开它。门底边还会进行有界落点交换，按实际路线的交叉、重叠和长度决定是否保留改动。后端拒绝无效方向、非有限数值及越界比例。

连线使用带圆角的正交路由，按实际线段检测节点障碍，优先选择局部短路径，并为分叉和汇合对齐公共通道；横向间距较小不会被视为回流。发生阻挡时比较附近的上下通道，复杂遮挡使用带转弯成本的网格搜索。用户入口同样参与避让，重复连线分配独立路径，拖动节点时重新计算。每条边生成初始避障路径后，整图以两轮有界候选搜索共同理线：比较交叉/碰触、非共用线段重叠、线长和转折数，仅接受不增加重叠的改善。候选来自节点间通道、现有线条旁侧和外围回流通道；共享起终点的分叉/汇合主干可以保留，普通重叠不能用来掩盖交叉。路线长度最多为初始长度的 1.6 倍加 120 画布单位，拐点数量也受限；密集图限制重新寻路次数，避免拖动时无界搜索。排序固定、同一图重复计算保持一致；这是一种减少交叉的启发式算法，不承诺全局最少或零交叉。日常自动理线只影响连线显示，不移动用户放置的节点，也不改变工作流的连接关系。

缩放控件左侧提供「优化布局」按钮。主动优化会将用户入口、主流程从左到右分层排列，将并行分支上下排开；归属明确的输入门/输出门与 Agent 成组靠近排列。布局先依据入口距离识别循环回边，再在去除回边的布局副本上分层，以有界重心排序减少跨层交叉。逻辑连接从不删除或反转，未连接节点和不完整草稿同样保留。主动优化解除所有手动落点并重新自动选边、排序和理线，最后适应视图；节点坐标与手动落点变化作为一次操作撤销/重做，并随工作流保存。重复优化不会不断漂移。

两条连线的直线段内部发生交叉时，竖线使用小圆弧跨过横线，并以画布背景描边分隔上下层。共享通道、分叉汇合点和圆角处不生成跨线桥；桥随缩放和选中状态显示，不改变流向或连接关系。

基本信息和图内容共享撤销/重做历史，删除节点同时记录其连线及规则引用，同一次拖动归为一步。平移和缩放只更新视口，不影响未保存标记或占用撤销步骤；点击保存时会一并持久化当前视口。

添加节点菜单的「智能体」分组提供「新建智能体」，可以拖入或点击添加；不再加载或引用子 Agent 模板。每个智能体节点代表一个待绑定的独立对话位置，对话可来自任意项目或不属于项目。用户节点和逻辑门保持独立。公共背景只有一个值，所有节点共享；节点分别存储接收说明、任务说明和交付说明。坐标和视口属于布局，不决定执行顺序。

智能体节点通过 `modelConfigId` 选择默认模型，通过必填 `permissionMode` 选择 `default`、`custom` 或 `full`，新建默认 `default`。顶部在原模板选择的位置显示权限下拉框，复用对话权限的名称和盾牌图标；右侧模型始终可选。权限仅保存为模板定义，不改变当前对话或工具授权。自定义权限引用软件现有的自定义权限模式，不在工作流里复制权限规则。

画布节点第二行展示模型名称。可选模型复用系统的权威可用性投影，已保存模型失效时保留原引用并允许重新选择，不静默切换。未选择模型的节点保存为草稿。保存格式不接受旧 `templateId`，也不做旧工作流转换。

## 图与规则

`schemaVersion: 1` 定义包含工作流基本信息、nodes、flows、boundaryPositions 和 viewport。`boundaryPositions.input` 保存用户输入入口的坐标，参与保存与撤销，必须显式提供。开发期直接更新 schemaVersion 1 的节点契约，旧工作流由开发者自行清理，不提供旧节点规则或字段缺省的兼容转换。Flow 两端各自是 `boundary` 或带稳定 `nodeId` 的 `node`，只有 source 允许是 boundary，target 必须是 node：

- boundary → node：用户提供的入口流。
- node → node：内部依赖，允许不同节点之间的回边，禁止自连接。
- node → boundary：禁止，固定用户入口不接收入流。

节点是严格的判别联合，每个节点有独立 ID：

- `agent`：默认模型、默认权限、接收说明、任务、交付说明；不再持有 inputRule/outputRule。
- `user`：公共节点字段与 task（需要用户做什么）。展示当前账户头像与用户名，配置页仅填写任务说明，没有模型或模板设置。输入复用输入门，第二条入流自动插门；输出可以直接连接多个目标，不自动创建输出门且禁止绑定输出门。目标 Agent 出现多入流时仍自动插入其输入门。缺少任务说明保存为草稿；已有仅展示的用户节点省略 task 时按空白说明读取。头像从账户上下文读取，不写入工作流。收到完整输入后显示「等待用户操作」，悬停显示任务，点击节点后通过「我已完成」确认结束该等待项；不会自动发送下游消息，用户自行在相应对话操作。
- `inputGate`：processingMode 与 busyPolicy；没有模板、模型或任务字段。
- `outputGate`：selection；没有模板、模型或任务字段。

逻辑门是独立可移动节点，用不同方向的三角形表示：输入门向右汇聚，输出门向左展开。三角形使用与普通节点一致的高对比实心背景，两侧可连接输入、输出，普通节点与逻辑门均不显示设置按钮；在选择/拖动模式中双击节点打开配置，也支持节点聚焦后按 Enter。关闭配置后焦点返回节点。连线模式下单击仅用于连接，连续双击不会额外创建自环或打开配置。门有独立名称，手动添加和自动插入时分别以「输入门1」「输出门1」等编号命名；顶部显示只读类型、可编辑名称与「配置」入口，端点选择器和配置面板使用该名称。画布保持三角形，不展示名称、规则摘要或 IN/OUT；配置面板直接显示规则。画布文字、线条、端口、边框和工具图标采用主题主文字色，深色主题浅色、浅色主题深色，网格背景维持低对比。连线、避障、适应视图使用每类节点的实际尺寸。

输入门只能有一个出口且连接 Agent 或用户，输出门只能有一个入口且来自 Agent；一个 Agent 每侧最多连接一个门，用户最多连接一个输入门，不能绕过输入门。单入单出 Agent 可直接连接。流股禁止起点与终点指向同一个节点（包括 Agent 和逻辑门）；画布连线与端点选择统一拦截，后端保存将自连接视为结构错误。不同节点之间的回路仍可使用。给 Agent 添加第二条入流/出流时，前端自动创建对应门，转接已有外部连线并保留连线 ID、名称和规则引用。已有门会被复用。转接到门的端点使用底边落点，另一端保持不变；新绑定保留 Agent 原有落点。手工将门连接到已有连线的 Agent，也转接已有连线。自动插门、重接和本次连线合并成一次撤销操作；容量不足则整个操作不生效。分支删除后保留逻辑门，不自动删除其配置。

输入门只保留两个正交选项，手动添加和自动插入的默认值均为 `batch` + `queue`：

| 字段           | 值         | 定义语义                                                                             |
| -------------- | ---------- | ------------------------------------------------------------------------------------ |
| processingMode | individual | 逐条处理：按消息到达顺序，每条消息形成一份输入。                                     |
| processingMode | batch      | 按批次处理：每条入流都有待处理消息时，各取最早的一条组成一批，剩余消息留在各自队列。 |
| busyPolicy     | queue      | Agent 忙碌时，完整输入按形成顺序排队；空闲后依次启动任务。                           |
| busyPolicy     | inject     | Agent 忙碌时，将完整输入补充给当前任务；空闲时启动任务。                             |

固定先组成输入、再决定投递方式；批次模式即使选择插入，也不能提前投递不完整的一批。输入一旦交付就不能重复使用；循环返回的消息仍按同一规则处理，没有首次唤醒、轮次、必选入口、N 条阈值或分组。输入门必须至少连接一条入流。上游互斥分支可能在多次执行中逐渐填满不同入流队列，不能仅凭单次输出数量就判定批次无法收齐。

输出门 selection：

| mode   | 出口约束                                     |
| ------ | -------------------------------------------- |
| all    | 全部输出                                     |
| one    | 恰好选择一条                                 |
| exact  | 恰好选择 min 条                              |
| range  | min 至 max 条                                |
| any    | 至少一条，协议支持，与 range 1..N 等价       |
| custom | required 必选，groups 各组 min/max，其余可选 |

必选项和分组不能重叠，组内流不能重复。删除连线会清理其引用，但保留空组及原数量要求，避免静默放宽规则。没有正数要求的 custom、阈值超出连线数量、门的归属不完整、多入/多出绕过门均保存为草稿。校验检查节点归属与图结构可达性，不证明任意循环的终止性、消息最终能否凑齐或任意复杂分支的运行可达性。

以上约束同时用于后端运行时校验；模型提交的出口集合必须完整通过校验，才会原子写入全部消息和回执。

## 权威校验与保存

`agent.workflows.request` 是设置页面的 Host RPC，不是模型工具。模板操作为 list、validate、save、delete、duplicate、saveDraft、deleteDraft；实例操作为 listInstances、saveInstance、setInstanceEnabled、deleteInstance。Electron 对请求/结果做严格字段解析，Rust 再执行结构和语义校验。编辑期间不发送 validate 请求，也不显示实时校验面板。点击「保存工作流模板」时检查版本及实例使用情况，再发送 save 请求，使用后端随保存返回的校验结果；若存在问题，保存为草稿并通过标准弹窗显示该次保存的问题，点击「知道了」关闭，列表不保留问题面板。前端不维护另一套图有效性算法。

结构损坏（不支持的版本、重复 ID、指向不存在节点的连线、无效坐标、超限数据）拒绝保存；名称/任务缺失、模型缺失、缺少用户入口连线、不可达节点、规则矛盾允许保存为草稿并返回 issues。每份图最多 128 节点、512 连线，序列化定义最多 2 MB，最多保存 1,000 份定义，定义目录总 JSON 大小不超过 16 MiB。

定义位于 SQLite `workflow_definitions`，通过 revision 乐观并发控制。新建 expectedRevision 为 0，更新和删除需匹配已保存 revision，冲突不覆盖新内容。图验证在事务内完成；列表重新计算 issues，工作流不再依赖子 Agent 模板表。v53→v54 只增加定义表和索引；v54→v55 曾增加独立于 Definition 的 enabled 字段并默认关闭，保留既有定义和历史；当前忽略这一历史字段，模板可用性由实时校验结果派生。

读取列表时，旧格式或损坏的定义按条目隔离，通过 `invalidRecords` 返回名称、版本和原因；暂存编辑草稿同样通过 `invalidDrafts` 隔离。原始 JSON 保留，不自动转换或删除，不影响其他模板加载、新建保存和实例管理。设置列表显示对应的不可用条目，用户确认后可删除模板或仅丢弃不兼容暂存，仍受版本和模板使用关系保护。模板仍被工作流使用时，删除不会在列表上方插入错误横幅，而是用标准警告弹窗列出正在使用它的工作流名称，并说明需先移除这些工作流，点击「知道了」关闭。单条不兼容记录不应导致整份目录请求失败或回滚其他模板的保存。真正的请求失败显示简短提示及可展开的错误信息，重试重新读取后端。

模板列表不显示「图结构已校验」标签，也没有手动启用开关。`WorkflowRecord.enabled` 仅表示后端当前校验的 `issues` 为空：有效模板保存后立即可选，未完成的模板仍可保存为草稿，修正并通过校验后自动恢复可选。列表重新校验发现模型等依赖不可用时，模板不再可选；前端不能通过手动切换绕过校验。模板可用不代表已有实例已开启，更不会启动模型执行。

## 全局工作流与对话绑定

左侧「工作流」提供新建实例、配置已有实例、实例启停和「管理工作流模板」。管理模板入口直接打开设置中的工作流模板列表，由用户在那里新建或编辑，不增加返回项目按钮或保存后的自动跳转。实例列表使用紧凑卡片，配置与删除均使用无框图标及悬停提示，不显示「已配置」标签或右侧箭头入口。页头只显示稍大的「工作流」标题，管理模板使用清单图标，创建入口为「激活新工作流」。模板列表提供快速复制，副本有独立 ID，不继承实例绑定。

新建实例先打开空白绑定画布，在顶部下拉框选择当前校验通过的模板；右上角操作为「激活」，未选择模板时不能激活。绑定画布沿用模板布局，用户和逻辑门只展示结构；智能体位置可拖入左侧任意项目或无项目的对话，不再展开右侧选择面板。配置页移除面包屑和底栏，「模版」选择、名称、所属项目、调色盘、解除分配与取消、确认操作集中在同一条顶部工具栏。未分配节点使用灰色背景，已分配节点使用高对比度背景和工作流颜色轮廓。顶部调色盘按钮展开单行颜色选项，禁用其他开启实例占用的颜色；新实例默认使用空闲颜色，颜色耗尽时明确提示。确认配置或开启实例时，在同一事务中检查开启实例之间的颜色唯一性，忽略十六进制字母大小写，防止并发操作重复占色。自身未冲突的颜色可保留；关闭或移除实例释放颜色，关闭的实例保留所选颜色但不占用它。选中已分配节点时，调色盘右侧显示解除分配按钮，只清空暂存绑定，不删除真实对话。节点的权限、模型和任务移入延迟 1 秒显示的悬停提示。右下角缩放按钮、百分比、分隔线和适应视图沿用模板画布样式。暂存选择不修改对话，只有确认时执行一个事务：

- 已有对话保留历史、项目及输入框内容；下一轮模型和权限按节点预设初始化一次，复用普通对话选择器的 Composer 草稿保存路径。
- 未绑定的智能体位置创建空对话，使用节点名称、模型与权限；新对话放入「所属项目」选择的项目，未选择则创建无项目对话，不发送初始化消息。选择只控制自动新建对话的归属，不限制跨项目拖入，也不移动已有对话。实例保存此偏好，项目被删除后清空为无项目。
- 同一对话全局唯一绑定，不允许跨工作流重复使用，也不能占用同一工作流的两个节点。拖入冲突或后端发现并发占用时，使用通用弹窗说明原因，仅提供「知道了」确认，不新增挤动画布的顶部错误栏。
- 替换对话仅初始化新绑定的模型和权限；未变的绑定、用户后续配置修改和模板配置变化均不追溯覆盖。
- 正在回复的对话也可新绑定：不触发即时模型转换，不修改当前 Run、Trace 或上下文，下一次发送仍通过普通模型切换流程生效。已有排队消息保留各自冻结的模型和权限。与普通对话选择器相同，模型转换或手动上下文压缩进行中暂不能初始化配置；运行中的工作流仍不能改绑或移除。

实例保存独立名称、颜色、新建对话的默认 `projectId`、模板版本、`enabled` 和节点到对话的绑定。确认激活或确认已有实例配置成功后，实例均处于开启状态。侧栏仅为开启实例的对话显示相同颜色标记，悬停显示实例名称。移除实例只解除绑定，不删除对话。确认前等待待保存的对话草稿，确认后通过普通对话草稿更新函数合并新模型和权限，保留同时到达的输入框、附件及队列变化，再补齐新对话；同步重试不重复初始化，避免 Renderer 缓存写回旧配置。保存请求有版本校验和幂等重试保护。

## 实例启停与归档

实例列表的开关对应持久化的 `WorkflowInstance.enabled`，通过 `setInstanceEnabled` 和 `expectedRevision` 做 CAS 更新；它与反映当前活动的 `running` 是不同状态。schema v57 为实例增加默认值为 true 的 enabled 列，开启仍须通过当前模板、完整绑定、未归档对话和颜色占用检查。开关失败或版本冲突不在前端伪造成功。开关使用局部等待状态，保持列表顺序、滚动位置及其他卡片的显示；已有目录后台刷新不卸载列表，且过期读请求不能覆盖开关更新后的状态。

开启实例的任一绑定对话或其子 Agent 正在运行时，卡片边框显示工作流专属颜色的流水灯，全部结束或关闭实例后停止。动画使用独立覆盖层，不移动卡片内容或替换按钮；系统开启减少动态效果时改用静态颜色轮廓。活动状态通过本地生成消息和任务生命周期事件更新，并在页面可见时低频校准后端状态；后台校准失败保留最近状态，不显示加载闪动，也不改变正在编辑的绑定。

实例卡片的配置按钮前提供「查看流程图」入口，进入独立的只读页面。页面沿用模板原有节点位置、逻辑门、流股和接线，不重新排列成智能体父子树；支持平移、缩放和适应画布。绑定节点显示对话名称，点击通过普通对话导航打开对应对话。每个节点分别根据该对话及其子 Agent 的真实活动呈现专属颜色的呼吸效果，不根据实例级 running 状态点亮所有节点；系统减少动态效果时使用静态轮廓。暂停工作流不隐藏这个只读入口，也不掩盖仍在执行的对话状态。对话顶部在文件夹按钮前显示工作流颜色的入口，直接打开所属工作流流程图；侧栏颜色标记仍只为开启的工作流显示。真实 `sent`、`delivered`、`waiting_user` 事件触发对应连线上的短暂流动动画；初次打开仅建立序列基线，不回放历史，不根据运行状态推测发送。

流程图节点使用白色背景和深色文字，并同时展示等待批准、等待交互和未读提示：等待批准优先于等待交互，未读使用独立标记，不因打开流程图而清除。审批合并对话本身及其子 Agent 的真实待批状态；等待交互复用全局提问状态，未读复用对话已读记录。运行节点的呼吸边框叠加同色环绕流水灯，动画覆盖层不改变卡片尺寸和文字位置；减少动态效果时保留静态轮廓。流水灯只沿节点边框运行，不代表流股发送了消息。

监视 hook 按 instance 与绑定 conversation identity 隔离状态，合并 Agent/协作事件并检查 sequence、Run 和请求 revision；旧 Run 的迟到终态不能熄灭新 Run。事件只触发有界校准，可见时每 5 秒补偿读取，focus/resync 恢复后重取权威树；失败保留最近投影。实例列表只为开启实例显示活动，独立流程图仍可观察已关闭实例中继续运行的对话。等待交互投影按会话分页读取请求并限制并发，迟到扫描不能覆盖更新事件，且不读取回答草稿或消息正文。

关闭实例保留名称、颜色、绑定、对话历史及当前输入内容，隐藏侧栏颜色标记并释放颜色，不中断或取消任何正在进行的对话 Run。再次开启前必须重新校验；若原颜色已被另一开启实例使用，需要选择空闲颜色。关闭不会解除对话的唯一绑定关系。

开启实例中的对话禁止归档，需先关闭实例。批量归档先在前端检查全批目标，存储层再以触发器校验每次写入，不能绕过保护；这不把多个独立归档请求变成一笔原子事务。关闭后的绑定对话一旦归档或删除，实例会保持关闭并标记 `needsReview`，补全绑定并确认前不能重新开启。正式保存模板变化会关闭相关实例并要求重新检查；读取时发现模型等依赖失效只改变模板的可选状态，不自动关闭已有实例。

## 模板修改与实例保护

保存正式模板前查询实例使用情况；确认令牌绑定实际使用关系，后端在写入事务里再次校验。未被使用时正常保存；被未运行的实例使用时，弹窗列出实例名及所关联的项目名称，确认后允许保存。实例运行状态来自后端，只有开启实例才投影绑定对话及其子 Agent 活动，前端不能声明状态来绕过保护。

任一实例运行时禁止覆盖原模板，只能把修改保存为独立副本或暂存到单独的模板编辑草稿。暂存不会改变正式定义或现有实例；重开编辑器恢复暂存内容。正式保存成功后清理对应暂存。被使用的模板不可直接删除。

正式更新模板后，关联实例关闭并标记为需要复核，释放颜色并隐藏侧栏标记。按稳定节点 ID 保留仍存在的绑定，删除节点只解除绑定，新增节点等待补全；确认新版本绑定后才恢复可用。模板更新不会删除对话，也不会初始化未变化绑定的模型和权限。

## 工作流运行与上下文

`workflow.execution` RuntimeExtension 使用同一次采样取得的后端快照，同时提供工具可用性、请求级能力说明和 Conversation World State section。section 包含工作流名称、公共背景、节点接收/任务/交付说明、前后节点、出口 ID 和逻辑门规则。身份在 Run 内冻结，后端实时检查实例是否仍开启及模板/绑定是否仍匹配；停用后的下一次采样移除发送能力并通过已有 CWS diff 机制更新上下文。checkpoint 不保存可恢复的授权，只恢复扩展结构。成员仍是独立根对话，子 Agent不继承工作流工具。不会自动插入「待命」用户消息。

节点先根据职责与实际进展判断是否需要向下游交付；没有需要交接的新信息、成果或待处理事项，且没有尚未完成的明确交付要求时，可以不调用 `workflow_send` 并结束本次处理。避免为了推进图或凑齐批次发送空洞、重复或占位消息。明确要求的交付仍须完成，批次门缺少入流时继续等待；批次由后端组装，收件节点无需再次等待。

`workflow_send({ outputs: [{ flowId, message }] })` 在决定发送后一次提交完整出口集合，不接收任意目标对话 ID，也不允许模型声明自己的来源。Host 绑定 conversation、Run、assistant message 与 tool call 身份；存储事务校验当前成员资格、冻结版本和输出门 all/one/any/exact/range/custom，再一起提交源消息、输入组装和幂等回执。相同 Run/tool call 的重放返回既有结果，不会重复投递。成功表示已持久接纳，不表示接收方已经完成任务。前端使用统一工作流图标和可读的正在发送/已发送状态，显示工作流及目标节点名称；展开后按目标展示发送原文文本框，右上角提供复制与跳转目标对话。用户节点没有对话跳转入口。名称和目标身份来自 Host 的发送快照，模型参数不包含这些身份信息。

输入门先按各条入流 FIFO 形成输入，再应用 queue/inject。**批次只生成一条组装消息**：工作流和所有来源节点、公共背景、当前接收角色只各出现一份，正文区域依次列出每个节点的原始消息，最后列出本节点任务、交付要求、目标出口及 `workflow_send` 用法。不会分别生成多条用户消息、多个指导项，或重复嵌套上游的上下文包装。

Core Server 后台推进完整输入，不依赖 Renderer 或看板打开。queue 在当前对话空闲后走正常根 Turn 入口，使用当前 Composer 模型/权限并遵循模型转换；inject 只在模型下一次安全采样边界进入，不打断工具、审批或用户交互。持久 input、run/delivery 绑定与专用 `WorkflowDelivery` Trace 负责恢复和去重。用户可见记录有 Host 提供的工作流来源标记与各来源原始正文，默认只展示实际消息；收藏按钮右侧可展开查看完整工作流包装，再次点击收起。批次按来源分别展示，复制遵循当前展开状态；不解析正文中的标题来推测消息边界，旧 Host 缺少原始正文时保留全文。此展示切换不修改持久消息或模型上下文；模型上下文把来信投影为协作内容，不赋予用户发言或审批授权。普通聊天记录中的展示副本不会再次作为 HumanText 进入模型。

后端保存消息、输入状态、事件序号、Run 工作流身份和 Stop 屏障。停止对话会暂停未消费输入，避免旧队列立刻重启该对话；重新开启工作流恢复可投递队列。模板或绑定变化会使旧输入失效。关闭实例阻止新发送和新投递，但不取消已有对话 Run。用户节点确认只更改所选 input ID 的状态，幂等且不会影响之后到达的新输入。投递结果无法确认的输入保留为 failed 并阻止后续 FIFO，不自动重发；节点显示「投递失败」，用户检查对应对话后可通过通用弹窗确认「跳过此来信」。该操作仅将明确选择的失败输入标记失效，再继续后续队列。

看板通过 `agent.workflows.request` 的 `runtimeSnapshot`、`completeUserInput`、`discardFailedInput` 及 `agent.workflows.runtime.changed` 读取状态。监测快照只传元数据，包含全部未结束输入及最近的历史，清空正文投影而不改变持久原文。通知丢失时补偿读取，界面不能借这些接口提交模型工具消息或调度对话。终态通过持久 run_completed 事件补偿聊天记录和未读同步，当前可见对话不会因后台完成写入而恢复旧未读标记。连线动画有实例和序号隔离，仅根据实际接纳/送达事件出现；减少动态效果时不播放。
