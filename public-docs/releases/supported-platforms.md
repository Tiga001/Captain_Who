# 平台与构建状态

MyCopilot 为以下操作系统提供原生打包入口，随附运行时的下载清单也登记了各平台的 arm64/x64 资源。但当前命令只在本机平台与架构上准备组件和打包；这些配置不能证明六种组合都已构建成功，也不能代替某个安装包的发布与验收记录。

| 操作系统 | 已登记的组件资源 | 打包形式            | 当前证据边界                                                                         |
| -------- | ---------------- | ------------------- | ------------------------------------------------------------------------------------ |
| macOS    | arm64、x64       | 应用与 DMG          | 正式构建强制 Developer ID、hardened runtime 与 DMG 签名；尚未配置 Apple notarization |
| Windows  | arm64、x64       | NSIS 安装程序       | 存在原生构建入口；尚无仓库内完整公开发行验收记录                                     |
| Linux    | arm64、x64       | AppImage、snap、deb | 存在原生构建入口；尚无仓库内完整公开发行验收记录                                     |

当前没有可核验的最低操作系统版本或各平台公开发行验收记录。因此，下表表达的是仓库中的**构建目标**，不是对全部组合的兼容性承诺。

macOS 构建还会核对 Core Server、Office Renderer、OfficeCLI、Artifact Runtime 等受管原生文件的精确签名清单，并扫描打包内容中的机器私有构建路径。通过这些门禁仍只证明当前产物满足仓库规则，不等于 Apple 已公证或已对外发布。

## 平台相关差异

- 原生终端和本地 MCP Server 会启动平台进程，行为受操作系统和本机权限影响。
- 旧版 `.doc` 读取当前只在 macOS 上通过系统转换能力提供；`.ppt` 和 `.xls` 不支持。
- 图片生成凭据在签名 macOS 构建中使用 Mac Keychain；开发构建和其他平台采用不同的凭据后端。
- Windows 上外部 stdio MCP Server 的完整进程树隔离尚不能作为已验证保证。
- Scheduled Automation 只有在应用与 Core Server 运行时才会执行，不是操作系统后台服务。
- 原生通知能否显示取决于平台支持和用户的系统通知设置。

## 安装前检查

1. 确认安装包分发方明确列出了你的操作系统与 CPU 架构。
2. 核对发布者、文件名和版本；只有分发方实际提供签名、公证或校验值时，才能据此验证。
3. 阅读[已知问题](../support/known-issues.md)，尤其是模型、MCP、浏览器、Office 与 Automation 相关限制。
4. 不要把其他平台的安装目录、组件缓存或应用内部文件复制过来作为安装方式。
