# 联网调研并撰写报告

## 目标

围绕一个明确问题完成检索、交叉核对和写作，并得到带来源链接、日期与不确定性说明的 Markdown 报告。

## 准备

- 在“设置 → 配置 → 联网搜索”中允许联网搜索并填写有效的 Tavily API Key。
- 建议选择一个专门保存报告的本地项目；如果只需要聊天答案，也可以不绑定项目。
- 不要在检索词中放入密码、Token、未公开代码或个人敏感信息。查询和目标网页地址会发送给搜索服务。

## 步骤

### 1. 把问题变成可验证的研究任务

示例：

```text
请调研 2026 年主流桌面 Agent 产品如何处理本地文件权限。

要求：
- 优先使用产品官方文档、发布说明和安全说明；
- 至少交叉核对 3 个独立来源；
- 区分“来源明确写出”和“根据资料推断”；
- 记录资料发布日期或访问日期；
- 不要根据搜索摘要直接下结论，必要时打开原页面；
- 最后把报告写入 reports/desktop-agent-permissions.md。

报告结构：结论摘要、逐产品比较、共同模式、差异与风险、来源列表。
```

把年份、范围、来源偏好和输出路径改成你的实际需求。

### 2. 观察搜索与读取过程

Agent 可能先搜索关键词，再读取具体网页。搜索结果只是线索；重要结论应尽量回到原始资料。遇到登录墙、动态页面或内容缺失时，应明确记录“无法核对”，而不是补写猜测。

### 3. 审核来源质量

在写文件前，要求 Agent 先列出准备采用的来源及各自支持的结论。优先级通常是：官方文档或原始数据，其次是可信的专业分析，最后才是聚合页和二手转述。

### 4. 批准报告写入

核对目标路径和报告预览后批准写入。报告中的链接应直接指向支持该结论的页面，而不是搜索结果页。

### 5. 做一次反向审查

继续发送：

```text
请只审查刚才的报告，不要扩大调研范围：找出缺少来源、来源与结论不匹配、时间可能过期或表达过度确定的地方。必要时修正并列出修改点。
```

## 预期结果

报告应让读者区分事实、推断和建议，每个重要、可能变化的事实附近都有可访问来源。文件存在且内容可打开，Agent 也明确说明了未能核对的材料。

## 失败处理

- **提示缺少 Tavily Key**：回到“设置 → 配置”完成联网搜索配置。
- **搜索结果为空**：缩短查询、使用同义词，或限定权威站点后重试。
- **页面无法读取**：换用该机构的其他官方页面；不要要求绕过登录、付费或访问限制。
- **来源互相冲突**：保留冲突，说明各自日期和口径，不要强行合并成一个答案。
- **报告写入被拒绝**：确认对话绑定了项目且写入权限允许目标路径。
- **时效性不足**：明确要求核对发布日期和“截至某日”；旧来源只能证明当时状态。

了解模型为什么需要 Tool 才能搜索网页，请读[Tool Calling](../learn/tool-calling.md)。
