# 创建一项定时自动化

## 目标

创建一个“工作日检查项目待办”的定时任务，先手动试运行，再理解暂停、审批、通知和恢复行为。

## 准备

- 至少启用一个模型；若要绑定项目，先添加该项目。
- MyCopilot 必须保持打开并成功完成启动，任务才会按计划运行。它不是操作系统级后台调度器，不会在应用退出时自行唤醒。
- 初次使用选择“默认”权限，避免后台任务获得不必要的完全权限。

## 步骤

### 1. 打开 Scheduled

点击左侧栏“已安排”，再点击页面右上角“创建”（空列表中显示“创建任务”）。填写任务名称和任务描述。描述要能够在每次运行时独立理解，例如：

```text
检查当前项目中的 TODO/FIXME 和最近变更，只报告新增或需要尽快处理的事项。
不要修改文件，不要安装依赖。若没有重要变化，请明确报告“无重要变化”。
```

不要依赖“像上次一样”这类隐含上下文；自动化应有稳定、完整的目标。

### 2. 选择运行目标

- **新聊天**：每次运行创建新的根聊天。选择项目和模型，适合独立日报、巡检和一次一份的报告。
- **现有聊天**：每次在所选根聊天追加一个回合，适合持续跟踪同一主题。

现有聊天只能选择仍可用的根聊天，不能直接把自动化绑定到子 Agent 对话。需要多 Agent 时，让自动化启动的主 Agent 在任务内自行分工。

### 3. 选择权限

“默认”“完全权限”“自定义”来自当前权限设置。保存时，任务会冻结当时解析出的权限，包括自定义模式中的内置执行策略：之后仅修改“设置 → 常规”中的自定义细节，不会自动改写已有任务；需要重新编辑并保存任务。

如果以后关闭完全或自定义权限模式，使用该模式的后续运行会被阻止。重新开启后仍需编辑一次被阻止的任务，系统不会静默扩权或自动修复。

### 4. 设置频率与通知

当前支持固定分钟/小时/天间隔、每天、工作日、每周，以及按小时、日、周、月、年组合的自定义重复计划。当前不支持 cron 表达式、一次性计划和结束日期。

时间按保存时电脑的当前时区记录，页面没有独立时区选择器。跨时区编辑并保存任务前，务必重新核对显示的时间。

通知选项会随目标变化：新聊天可选择所有运行或仅未成功；现有聊天可选择重要更新或仅未成功。它与“设置 → 常规”中的普通任务通知策略相互独立。原生通知用于提醒，权威结果仍以“已安排”页面的运行历史和实际聊天为准。详见[系统通知](../capabilities/notifications.md)。

### 5. 保存并立即试运行

点击“创建任务”，然后打开该任务的“更多操作”菜单，选择“立即运行”。观察运行历史：它可能依次显示已排队、正在启动、正在运行，最后进入已完成、运行失败或已取消；需要操作时会显示“等待批准”。

打开这次运行对应的聊天，核对实际结果是否符合任务描述。后台审批仍必须由你决定，不会因为它是定时任务就自动批准。

### 6. 日常维护

- “暂停”只停止未来计划，不会取消已经开始的 Run；暂停任务仍可以“立即运行”。
- 编辑目标、模型、权限或时间后保存，新的配置只影响未来 Run。
- 删除任务会停止未来调度并请求取消活动 Run，但以前已经创建的聊天不会随之删除。
- “需要关注”徽标表示失败、等待审批、重要更新或配置需要修复；“标记为已处理”不会改变任务或 Run。

## 预期结果

任务出现在“已安排”列表，能成功完成一次“立即运行”，并在运行历史中打开对应聊天。下一次运行时间、权限和通知策略与你保存的配置一致。

## 失败处理

- **计划时间没有运行**：确认应用当时是否保持打开且启动成功。离线错过的多个时点会在下次启动合并为一次恢复运行，不会逐次补跑，也不承诺秒级准点。
- **显示“需要修复”**：目标聊天、项目路径、模型、权限或计划可能已失效。打开任务选择有效配置并重新保存。
- **一直等待批准**：回到对应根聊天处理审批；当前没有独立审批超时。
- **已有运行正在进行**：同一任务一次只能有一个非终态 Run，等待其结束后再立即运行。
- **想停止活动 Run**：当前界面没有单独的 Run 停止按钮。暂停只影响未来计划；删除会请求取消，但应随后检查最终状态。
- **没有收到系统通知**：仍到运行历史检查。当前不会用应用内提示替代未能送达的系统通知。
