# 使用多个 Agent 并行工作

## 目标

把一个可拆分的项目任务交给主 Agent（原理文档也称根 Agent），由它创建子 Agent 并行调查，最后在主对话汇总带证据的结论。

## 准备

- 必须使用一个已添加的项目，并确保至少一个启用模板已分配给该项目。
- 至少启用一个可用模型。
- 选择能真正独立推进的子任务，例如“前端入口”“后端数据流”“测试覆盖”。强依赖的串行步骤不适合硬拆并行。

## 步骤

### 1. 创建子智能体模板

打开“设置 → 子智能体”并点击“新建模板”。填写：

- **名称**：例如“前端审查员”；
- **简短描述**：告诉主 Agent 什么时候应选择它；
- **指令**：限定职责、输出格式和禁止事项；
- **模型**：选择已启用模型。
- **适用项目**：勾选这次任务使用的项目；一个模板可以分配给多个项目。

保存后确保模板为“已启用”且已分配目标项目。模板变化只影响未来创建的子 Agent，已经创建的节点保留创建时的快照。

可以为不同职责再创建“后端审查员”和“测试审查员”。模板越聚焦，主 Agent 越容易正确分工。

### 2. 在主对话明确要求协作

新建项目对话并发送：

```text
请分析“用户保存设置”这条完整链路。使用子智能体并行调查：
- 一名负责前端交互与状态；
- 一名负责后端持久化与校验；
- 一名负责测试覆盖和缺口。

你负责协调和最终交叉核对。子智能体只读分析，不修改文件。最终回答必须区分三路证据、一致结论和冲突点，并引用关键文件。
```

主 Agent 决定是否以及如何调用协作工具。清楚写出“使用子智能体”和可独立的分工，能减少它改为单 Agent 顺序处理的可能。

### 3. 在右侧栏观察

打开右侧栏的“子智能体”。列表会区分进行中与已结束的子 Agent；打开某个子 Agent 可以只读查看它的对话和状态。用户不能在子对话中直接发送消息或启动新一轮处理。

如果子 Agent 请求文件、命令或其他审批，回到主对话处理。批准前仍要核对动作本身，不能因为请求来自子 Agent 就默认信任。

### 4. 要求主 Agent 汇总

等待主 Agent 收集结果后，检查最终回答是否处理了互相矛盾的结论。必要时让主 Agent 把某一项返工或追问；子 Agent 完成一次任务后不会被删除，主 Agent 仍可向它发送后续任务。

## 预期结果

右侧栏“子智能体”中出现多个有明确任务名的子 Agent，主对话最终收到综合结论。子 Agent 的原始调查仍可只读查看，最终答案不是简单拼接，而是经过主 Agent 对照和取舍。

## 失败处理

- **没有可选模板**：确认已经选择项目、模板已启用、所绑定模型仍可用。
- **主 Agent 没有并行分派**：把独立子任务和“请使用子智能体”写得更明确；模型仍可能判断任务太小，无需并行。
- **任务互相阻塞**：重新划分边界，让每个子任务有独立输入和交付物。
- **子 Agent 等待审批**：只在主对话处理；子 Agent 查看页是只读的。
- **显示“结果未知”**：不要让系统自动重做可能产生外部副作用的步骤，先检查实际文件或外部状态。
- **子 Agent 过多**：减少分工。系统有并发和树规模限制，并行数量不等于完成速度线性增长。
