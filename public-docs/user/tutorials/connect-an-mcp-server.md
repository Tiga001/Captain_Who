# 连接本地 MCP Server

## 目标

把一个可信的本地 MCP Server 接入 Captain Who，确认工具目录可用，并在对话中完成一次受控调用。

## 准备

- 从该 MCP Server 的官方说明获得准确的可执行文件、参数和工作目录。
- 先在终端中按服务方说明完成安装；Captain Who 的添加页面不会替你安装程序或依赖。
- 当前用户配置的 MCP Server 只支持本地 **stdio**。HTTP、Streamable HTTP 和 OAuth 接入尚未开放。
- 不要把 Token、密码或 Cookie 放在命令参数、工作目录或服务器名称中。当前管理界面也不提供自定义环境变量或请求头配置。

## 步骤

### 1. 添加服务器

打开“设置 → MCP”，在“外部”区域选择“添加服务器”。填写：

- **名称**：便于识别的本地名称；
- **可执行文件**：通过系统选择器选择实际程序；
- **参数**：严格按顺序逐项填写；
- **工作目录**：选择服务运行所需目录；
- **工具调用策略**：初次连接建议选择“每次询问”。

保存配置。新服务器不会因为“已保存”就自动获得启动和工具调用权限。

### 2. 核对并授权启动

点击启用时，Captain Who 会展示将要启动的本地程序、参数和相关入口。逐项核对后确认。若以后替换了可执行文件、代码入口或配置，原启动授权可能失效，需要重新核对。

启动授权说明“允许启动这个精确配置”，不代表该进程处在沙箱中，也不等于允许它的所有工具自动执行。

### 3. 等待服务器就绪

状态通常会经历“正在启动”“正在发现工具”，最后到“已就绪”。打开服务器详情并加载工具目录，确认目录完整且能看到预期工具。

目录显示“部分”“已过期”或“失败”时，工具不会被当作完整可调用目录；先刷新或修复服务器，不要根据残缺列表继续操作。

### 4. 在对话中测试

新建一个低风险任务，明确指定目标但不要假设工具名称，例如：

```text
请查看当前可用的 MCP 工具，使用“本地知识库”服务器查找关于发布流程的只读资料。先说明准备调用哪个工具和原因，不要执行任何写入操作。
```

审批卡片出现时，确认服务器、工具、理由和参数结构，再批准或拒绝。来自 MCP Server 的工具名称、描述和“只读”标记都只是第三方提供的信息，不能单独作为安全依据。

## 预期结果

服务器详情显示“已就绪”，工具目录完整；对话时间线能显示来自正确服务器的 MCP 调用及成功或明确失败的结果。

## 失败处理

- **需要启动授权**：重新打开详情，核对当前可执行文件、参数和工作目录后授权。
- **启动失败或反复重连**：先用服务方文档在本机验证该程序；检查参数顺序和工作目录。
- **没有工具**：区分“完整但为空”和“目录不完整”。后者需要刷新或修复连接。
- **审批参数不可用**：重启后某些未完成审批可能无法继续；取消后发起新的明确调用。
- **调用结果未知**：请求可能已经送达 MCP Server。先检查外部系统状态，不要立即重复写操作。
- **需要密钥**：不要放进参数。当前管理界面不支持环境变量或 SecretRef，因此无法安全配置依赖这类密钥注入方式的服务器；请改用不需要该配置方式的服务器。
