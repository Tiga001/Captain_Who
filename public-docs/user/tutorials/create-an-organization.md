# 创建并运行一个组织

本教程创建一个两人调研组织：研究员收集证据，审阅员检查证据与结论，再通过组织邮件交流。

**版本范围：以下操作针对截至 2026-10-04 已核验的当前开发版本，不代表所有已发布安装包都包含组织能力。** 如果没有看到“组织”，先检查[发行说明](../../releases/release-notes/README.md)和实际应用版本。

## 开始前

- 已完成账户登录、软件许可验证，并配置至少一个可用模型。
- 本例先使用默认权限，不处理机密信息，不发送外部消息，也不修改文件。
- 如需联网搜索，先准备[联网搜索](../everyday-use/search-and-browser.md)所需配置；没有搜索配置时，可用你提供的公开资料做本例。

组织成员是独立对话，可以直接与每位成员交互；本教程不创建 Multi-Agent 子任务树。两者的适用场景见[组织](../capabilities/organizations.md)。

## 1. 创建模板

从左侧栏打开“组织”，选择“管理组织模板”，再点击“新建组织模板”。也可以从“设置 → 组织”进入模板列表。

在“基本信息”中填写：

- 名称：调研与审阅
- 简短描述：收集公开证据，并交叉检查结论
- 组织公共背景：只处理用户指定的公开资料。区分事实与推测，为结论提供来源。不得对外发送消息、注册账户或修改文件；有不确定事项应明确说明。

公共背景会提供给组织成员，适合放共同目标与边界。不要填写 API Key、密码或其他不应发送给模型的秘密。

## 2. 配置两位成员

切换到“组织设计”，从“添加节点”中创建两个智能体。分别设置唯一名称、可用模型和默认权限。

| 配置项               | 研究员                                     | 审阅员                                             |
| -------------------- | ------------------------------------------ | -------------------------------------------------- |
| 这个节点会收到什么   | 用户指定的问题、公开资料和审阅反馈         | 研究员提交的来源、结论和疑点                       |
| 这个节点需要做什么   | 收集证据，区分事实与推测，向审阅员发送材料 | 核对来源是否支持结论，找出遗漏或冲突，向研究员回复 |
| 这个节点需要交付什么 | 有来源的简短结论，列出仍未解决的问题       | 可核对的修改建议和审阅结论                         |

本例不需要管理员或部门，保留普通成员、默认职级即可。拖动节点只调整布局，**不要寻找连线或输入/输出门**；成员可以直接按姓名互相发信。

点击“保存组织模板”。保存成功只建立模板，尚未创建成员对话，也不会启动模型。

## 3. 激活组织并检查对话绑定

1. 返回左侧“组织”首页，点击“激活新组织”。
2. 选择“调研与审阅”模板，填写这次组织的名称，并检查组织颜色。
3. 可选“所属项目”。自动创建的对话会放入此项目；选择“无项目”也可以。
4. 本例让两位成员保持“保存时新建对话”。若要复用对话，使用“绑定对话”或拖入已有的独立对话，不能将同一对话重复分配。
5. 点击“激活”。

现在列表会出现组织及两个成员对话。没有待处理邮件时，成员保持空闲，这是正常状态；激活不是自动开始本例任务。

## 4. 给研究员发起任务

点击该组织的“组织看板”，双击“研究员”打开对话。可以发送：

> 请根据我接下来提供的两篇公开资料，比较两种方案的适用场景。先整理关键结论及来源，发送组织邮件给审阅员，请他核对证据并指出遗漏。收到有用反馈后给我一版简短结论；有依据不足的地方请明确说明。不要对外发消息或修改文件。

随后提供资料或明确的公开链接。若希望主动联网调研，应在任务中明确问题、范围和来源要求，并确认搜索配置可用。

研究员发信后，空闲的审阅员会接手邮件开始工作；你无需手动向每个人重复发送同一任务。成员正在运行时，新来信先留在收件箱，由成员决定是否在当前回合领取。

等待同事时，成员可能正常结束回合，之后由新邮件再次唤醒。这不表示整个调研已经结束，应以实际交付和验收结果为准。

## 5. 在看板核对过程与结果

- 单击成员，查看待处理、处理中和历史邮件。
- 双击成员，阅读完整对话、审批和结果。
- 查看研究员发出的材料与审阅员回复，核对来源是否支持最终结论。
- “已处理”不等于结论正确；动画只表示传输，不是验收证据。

本例的完成条件是：两位成员完成必要交流，研究员给出可核对来源的结论并说明未解决问题。只有“收到”“待命”等往返消息不算完成。

## 6. 调整与结束

要调整职责或模型，回到组织首页打开“配置”，修改后点击“保存”。已激活组织拥有独立配置，修改模板不会改变它；保存一个停用组织也不会自动启用。

希望暂停新的组织协作时，点击“停用组织”。已经运行的成员不会因此停止；若要停止当前任务，打开其对话点击停止。手动停止后，待处理邮件会保留，向该成员对话发送新消息才能恢复正常自动收信。

启用组织中的对话不能归档。需要整理这些聊天时，先停用组织，再按正常流程归档；重新启用前恢复或重新分配有效对话。

## 7. 加入部门与分层管理

熟悉两位成员发信后，可以在现有组织的“配置 → 组织设计”中建立以下结构：

1. 添加“研究部”部门框，将研究员完整放入其中；再添加独立的“评审部”框，放入审阅员。部门可以完全分离或完整嵌套，不能部分交叠。
2. 选中研究员，在“职级”页设为职级 2、部门管理员。审阅员保持职级 1、普通成员。
3. 新增智能体“负责人”，放在部门框外，设置职级 3、组织管理员，并选好模型和权限。任务填写“维护组织成员职责，协调研究与评审”，交付要求填写“说明成员调整和最终交付状态”。保存时为它新建对话。
4. 点击“保存”。负责人尚未收到任务或邮件时保持空闲。

这时，负责人能管理职级更低的研究员和审阅员；研究员只能管理研究部及下级部门中职级更低的成员，不能管理评审部的审阅员。研究员与审阅员仍然可以直接互发邮件，部门和职级不会把邮件限制成单向或逐级转发。

双击研究员，尝试一个范围明确的管理任务：

> 在研究部新增一名普通成员“资料核对员”，职级 1，职责是核对引用与原文是否一致，交付有来源的差异清单。保留默认继承的模型与权限。创建成功后，给他发一封组织邮件，请他检查我提供的公开资料。

核对回执、部门归属和新对话：人员创建与发信是不同操作，新成员不会仅因被创建就开始工作。研究员也不能为新成员授予超过自己本轮实际配置的工具权限。

若要修改评审部成员，应交给有相应权限的负责人，或由你在组织配置中调整；不要只提高研究员职级来猜测会获得全组织管理权。高职级和管理身份是独立设置。

也可以在研究部内部画出“资料组”，形成“研究部/资料组”层级。删除画布上的部门框会保留成员并重新计算归属；让 Agent 通过人员管理删除部门时，则须先将其直属成员和下级部门移走，只有空部门可删除。

## 遇到问题

- **没有可用模板**：先保存至少一个通过校验的组织模板，检查每位成员的名称、职责和模型。
- **启用失败、提示模型不可用**：按弹窗列出的模型和成员修复模型设置，或在组织配置中替换模型。
- **颜色被占用**：选择其他颜色，或先停用/调整占用该颜色的组织。
- **对话不能分配**：确认不是子 Agent、不是已归档对话，也未绑定到其他成员或组织。
- **有待处理邮件却不运行**：检查组织是否启用、成员是否被手动停止、是否在等待审批/用户交互，以及模型和执行容量是否可用。不要反复发送同一任务。
