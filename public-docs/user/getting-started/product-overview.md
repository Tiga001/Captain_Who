# 产品概览

Captain Who 是一款本地优先的桌面 Agent 工作助手。它不只生成一段回复，还可以在你授权的范围内读取项目、搜索资料、调用工具、修改文件、运行命令，并把复杂任务分给多个子 Agent。

## 它和普通聊天工具有什么不同

普通聊天通常是“一问一答”。Captain Who 会围绕目标重复执行一个工作循环：理解任务、选择下一步、调用工具、查看结果，再决定继续、请求审批或结束。这就是 Agent 的基本工作方式。

例如，当你要求“找出这个项目启动失败的原因”时，Agent 可以依次查看目录、搜索配置、读取日志、运行测试并汇总结论，而不是只根据你粘贴的一小段文字猜测。

## 当前适合的工作

- 阅读和梳理本地项目，搜索文件与代码。
- 通过可审批、可审阅的 FileChange 创建、修改和删除文件，并查看 Git 未暂存、已暂存及上一轮变更。
- 运行受管的非交互命令，执行构建、测试和数据处理。
- 使用 Tavily 联网搜索和读取网页。
- 手动浏览网页，管理浏览/下载历史，或经授权让 Agent 控制应用内浏览器。
- 读取附件，处理 Word、Excel、PowerPoint、PDF 和图片。
- 安装或选择 Skill，为特定任务提供教学步骤和专用能力。
- 连接本地 stdio MCP 服务器，使用其提供的工具。
- 让多个子 Agent 并行研究、实现或审查不同子任务。
- 在需要时主动压缩上下文、从安全历史位置创建聊天分支，或让根 Agent 向你提出必要问题。
- 在一个项目中组织多个本地文件夹，并在 Git 审阅中查看未提交改动、选定提交或相对基准分支的差异。
- 创建 Scheduled Automation，让任务按计划在应用运行时执行。
- 为普通任务和 Automation 配置系统通知、声音和内容预览。

能力是否可用还取决于当前操作系统、模型服务、项目、权限、运行组件和第三方配置。请以界面的可用状态和对应能力文档为准。

## “本地优先”具体指什么

对话、项目记录、设置、审批状态和任务历史主要保存在本机；项目文件也不会因为添加到 Captain Who 就自动上传到某个 Captain Who 云端。模型密钥和本机 Token 活动同样不会随账户同步。

账户资料和软件许可是例外：它们需要与 Captain Who 的账户服务交互，用于登录和判断能否启动新的 Agent 回合。这不等于把项目、对话或模型密钥同步到该账户。

但是以下数据会离开本机：

- 发给模型的提示词、必要上下文和工具结果会发送到你配置的模型 API。
- 启用联网搜索后，查询词或目标网址会发送给 Tavily。
- 启用图片生成或 MCP 后，相关输入会发送给你配置的服务或本地进程。
- 浏览网页会像普通浏览器一样连接相应网站。

因此，在处理机密内容前，应先确认每个服务商的数据政策和你的组织规则。

## 当前不应期待的能力

- 当前正式公开发行仅支持 macOS 12 及更高版本的 Apple Silicon 设备；其他平台的构建目标不等于公开支持。
- 启动新的 Agent 回合需要登录 Captain Who 账户并拥有可用的软件许可；这不替代模型 API 配置。
- 没有跨设备的对话、项目、文件、执行记录、模型密钥或 Token 活动同步服务。
- 应用不是完全离线模型运行器；常规任务需要可用的模型 API。
- 权限策略不是操作系统级容器，完全权限也不意味着所有危险命令都会放行。
- Scheduled Automation 不会在应用退出时由操作系统后台唤醒，也不保证秒级准点。
- 多 Agent 是树状协作，不是可视化工作流或任意流程编排器。
- 右侧栏“文件”是只读预览器；Office 文件不能直接在该预览器中渲染。
- 当前没有统一的跨设备 Artifact 永久库，也没有一键清除全部本地数据的用户入口。
