# 上下文与历史

“对话保存在本机”和“模型当前能看到全部历史”是两件不同的事。对话可以长期保存，但每次模型请求都有有限的上下文窗口。

## 当前上下文包含什么

一次模型请求通常会组合：

- 当前对话中仍有效的用户消息和助手回复。
- 已完成工具调用的安全结果。
- 当前项目、权限和运行状态的必要说明。
- 已选择或已激活 Skill 的指令。
- 自动压缩产生的历史摘要和精确回查入口。

界面时间线用于展示，不等于模型上下文本身。隐藏推理不会作为普通聊天内容展示；为保持同一服务商的连续性，运行时仍可能保留必要的专用续接状态。凭据、私有存储路径和不适合发送的数据不会仅因为出现在内部流程中就成为普通上下文。

## 连续聊天时如何保留上下文

一轮结束后，下一轮会沿用尚未压缩的消息、工具交换、当时读取的附件内容、Skill 说明和运行状态记录。旧 Skill 说明和权限状态只是历史，不会自动重新开启能力或获得执行许可。

这种连续排列有助于复用服务商的前缀缓存，但实际命中率还取决于服务商、缓存有效期、工具列表和当前设置。压缩历史、切换服务商或改变能力开关时，共同前缀仍可能变化。

历史图片会继续占用上下文。当前文本摘要不会自动替代图片；应用会保留原图及其关联说明。若本地历史图片缺失或内容校验失败，应用会报错，避免在丢失图片的情况下继续请求模型。

## 查看上下文使用情况

如果当前构建启用了上下文指示器，可以在“设置 → 常规 → 输入框”开启“显示上下文窗口使用情况”。输入框会显示已用比例和 token 数。

这个数字基于 Captain Who 组装的上下文和模型配置的窗口大小。若你填写的模型窗口大于服务商实际支持值，接口仍可能拒绝请求。

## 自动压缩是什么

当历史接近安全容量时，Captain Who 会：

1. 选择一个完整的旧历史前缀。
2. 让模型生成结构化摘要。
3. 保存摘要和少量精确索引。
4. 用摘要替代旧前缀，再继续任务。

时间线中可能显示“正在自动压缩上下文”“上下文已自动压缩”或失败状态。压缩的目标是保留任务含义、决策、未解决问题和重要证据，不保证逐字保留所有旧内容。

对话很长时，可以主动让 Agent 写一份“当前状态、关键决定、待办和验证结果”到项目文件，再开始新任务。这通常比依赖无限历史更可靠。

## 历史回查

Captain Who 会为已完成工具活动保存有界的审计历史；部分大文本还可以按页精确回查。Agent 在需要时可以使用对话历史能力寻找旧结果，界面可能显示“正在回忆”。

边界包括：

- 单次捕获和上游工具都有大小限制。
- 二进制、秘密和隐藏推理不会进入普通历史归档。
- 上游本来就截断的内容无法由历史恢复。
- 本地对话搜索是关键词搜索，不是向量语义记忆。

因此，不应把对话历史当作无限、无损、跨设备的知识库。

## 主动压缩上下文

聊天空闲时，在空白输入框键入 `/`，选择“压缩上下文”。可以继续输入“压缩”或 `compact` 筛选；鼠标悬停或方向键选中后，按 Enter 执行，也可以直接点击。

时间线会显示“正在压缩上下文”，完成后同一分割线显示“上下文历史已压缩”。页面上的原始聊天消息仍然保留；压缩改变的是后续模型请求使用的历史。压缩过程中不显示取消按钮；失败或中断时会保留原上下文。没有新的可压缩内容时不会请求模型。

压缩成功后，分割线右侧会出现分支按钮。聊天空闲时，可以从这次压缩完成的位置创建新聊天分支；之后继续聊天也不会改变这个按钮对应的历史位置。若要从当前最新可用位置创建分支，请在空白输入框键入 `/`，选择“创建聊天分支”，或输入 `fork` 筛选。没有完整回复时，这项命令不可用。

压缩本身可能产生一次模型请求，其用量和费用独立计入“使用情况和计费”，不会覆盖上一条回复的用量。重启后中断的压缩不会自动再次调用模型。

## 切换模型时的上下文

当新模型使用不同 API 厂商或兼容规则时，Captain Who 会要求“压缩并切换”。这是为了把旧服务的专用状态转换为新模型可以安全消费的摘要，而不是把不可兼容的内部片段直接发送过去。

任务运行或等待审批时不能切换。转换失败时，原模型选择和历史保持不变，应先处理错误，不要反复切换。

## 分支、归档与删除

- **创建聊天分支**：快捷命令从当前最新安全完整位置创建分支；回复、模型转换或手动压缩成功分割线上的分支按钮从各自对应的历史位置创建快照。只能在聊天空闲时使用，新旧对话之后互不同步，历史费用不会重复计入。
- **归档**：从主列表移出，但可以在设置中恢复。
- **永久删除**：删除本地对话内容和关联授权，无法从界面撤销。
- **移除项目**：删除该项目在 Captain Who 中的对话和附件记录，但不修改项目目录文件。

对话的附件和受管产物有各自的授权与保留方式。同一可信 Agent 任务树中的父子 Agent 可以使用共享的附件、产物和 Agent 浏览器下载引用；无关任务不会因此获得访问权。当前没有统一的永久 Artifact 库或用户可配置的长期保留承诺；重要文件应显式保存到你管理的目录。

## 数据安全

对话和设置主要保存在本机，但发给模型的上下文会到达你配置的 API。不要在聊天中放入不需要模型处理的秘密。当前也没有跨设备同步或一键导出全部历史的公开功能。
