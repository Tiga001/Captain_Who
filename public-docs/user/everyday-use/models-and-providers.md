# 模型与服务商

本页适用于 [1.0.7 正式版](../../releases/release-notes/1-0-7.md)。Kimi K3.1、智谱 GLM-5.3 和新的厂商型号选择界面已随该版本发布，1.0.6 安装包不包含这些新增接入。

Captain Who 不附带可直接使用的模型账户。你需要提供一个兼容的 API 地址、Token 和模型标识。

新安装的模型目录为空，不会自动创建或启用示例模型。这样可以避免把占位模型误认为已经连接；首次使用必须明确新增至少一个模型。

## 当前兼容方式

当前运行时支持以下模型接入：

- OpenAI Chat Completions 兼容接口。
- Anthropic Messages 兼容接口。
- DeepSeek V4 Chat 专用配置。
- Moonshot 专用配置。
- 智谱国内标准 API 的 GLM-5.3 与 Flash 系列专用配置。

“兼容”表示接口需要满足 Captain Who 使用的消息、流式输出和工具调用约定，不保证所有第三方代理或自建网关都能工作。第一次真实任务才会验证服务端响应。

通用兼容模式根据完整 API URL 选择请求格式：包含 `/chat/completions` 时使用 OpenAI 兼容格式；包含 `anthropic` 或以 `/messages` 结尾时使用 Anthropic 兼容格式；其他地址默认按 OpenAI 兼容格式处理。

## 配置默认连接

1. 打开“设置 → 配置”。
2. 在“模型配置”中填写默认 API URL 和 API Token。
3. 使用服务商的完整 HTTPS API 地址，并填写对应 Token；正式安装包要求 HTTPS，开发/测试构建才允许本机回环 HTTP。
4. 在“可用模型”中开启希望出现在任务选择器里的模型。

继承默认连接的模型会共用这组地址和 Token。修改默认地址后，只影响仍使用默认连接的模型。

## 新建或编辑模型

点击“管理模型”，可以新建、编辑、删除或启停模型。主要字段是：

- **模型 ID**：原样发送给服务商，必须与接口实际接受的值一致。
- **显示名称**：只影响界面，不改变路由。
- **上下文总窗口**：由你按服务商支持范围填写，应用不会根据型号自动预填。留空时按 128,000 tokens 保存；部分型号会因容量不足而无法保存，应按提示修正。
- **支持图像输入**：通用兼容配置可手动声明；专用厂商配置由所选型号决定。开关不会让纯文本接口自动获得视觉能力。
- **输入、缓存输入、输出价格**：用于本地估算，每 1,000 tokens 计价。

在“更多”中可以为单个模型填写独立 URL 和 Token。可以先保存未填完整的配置，但补齐前不能用于连接。Captain Who 不会把单个模型的 URL 与全局 Token 混用，也不会反向混用。

“API 厂商”默认使用通用兼容配置；当前还可以选择 DeepSeek、Moonshot 或智谱专用配置。专用厂商的模型 ID 使用已适配型号下拉列表，URL 随厂商固定，图片能力随型号变化。不同模型族可显示不同的思考或推理强度选项；只使用界面为当前模型资料显示的选项，不要把某个模型族的参数套用到其他模型。服务商专用选项只在对应配置下生效。

Moonshot 列表包含 Kimi K3.1 Pro 及其高速版，使用与 Kimi K3 相同的推理强度设置；K2.7 Code 和 K2.6 的选项不同。完整型号与操作见[Moonshot Kimi 配置](../../integrations/model-provider-integration.md#moonshot-kimi-配置)。

智谱支持 GLM-5.3、GLM-5.3-Flash、GLM-5.3-FlashX 和 GLM-5.3-FlashX-Legal，使用国内标准 API Key 按量计费，不接入 Coding Plan 套餐或海外 Z.AI。旗舰型号只接收文本，Flash 系列可接收图片；四款均强制思考，可选择推理强度。具体地址、上下文和价格参考见[智谱 GLM-5.3 配置](../../integrations/model-provider-integration.md#智谱-glm-53-配置)。已有模型不会因新增智谱支持而自动切换厂商或修改配置。

## 在任务中选择模型

新建对话或 Automation 时，从模型选择器选取一个已启用模型。没有连接信息的模型不会成为可用选项。

在已有对话里切换模型时：

- 同一兼容边界内可以直接切换。
- 切换 API 厂商或兼容规则时，应用会要求先压缩历史，再切换。
- 普通运行期间可以预选下一轮模型，不会替换当前运行的模型；审批或阻塞问题占用输入区时，先处理当前面板。真正发送下一轮前才检查兼容性，并在需要时确认“压缩并切换”。

压缩会保留任务摘要和必要索引，但不会把全部历史逐字发送给新模型。重要事实应在切换前写入项目文件或在提示中重新说明。

## 用量和费用估算

在“设置 → 用量与费用估算”可以按时间和模型查看请求数、输入、缓存输入、输出及 thinking tokens。打开“对话 token 详情”后，每条模型回复下方可以显示本次用量。

费用是根据你填写的每 1k token 单价在本地计算的估算：

- 不代表服务商最终账单。
- 不区分币种。
- 缺少有效价格的消息不会计入估算。
- 清空统计不会删除历史对话中的 token 详情。

## 数据与凭据

模型请求会把提示词、必要历史和工具结果发送到所配置的 API URL。当前 SQLite 只保存模型凭据的不透明引用和状态；密钥由独立 Credential Store 保存。具备稳定签名身份的发行构建使用操作系统凭据存储，未签名 macOS 开发构建使用权限收紧的私有文件。应用不会读回已有 Token；应继续保护本机账户、完整数据目录、备份和磁盘访问权限。

不要把 Token 放进聊天、项目文件、终端命令、MCP 参数或截图。

## 常见问题

- **鉴权失败**：核对 Token 是否属于该 URL，是否含多余空格。
- **模型不存在**：模型 ID 与服务端实际名称不一致。
- **响应无效**：接口虽然宣称兼容，但工具调用或流式格式不满足要求。
- **图片不能发送**：所选模型未启用图像能力，或服务端实际不支持。
- **上下文超限**：配置的窗口大于服务商真实限制，或当前历史需要压缩。
