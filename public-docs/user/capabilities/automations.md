# Scheduled Automation

Scheduled Automation 用来按计划启动一个普通根 Agent 任务。它不是简单提醒：每次 Run 都可能读取项目、调用模型、使用工具并产生文件或外部副作用，因此创建时必须认真选择目标和权限。

产品界面的入口叫“已安排”。本页中的“浏览器自动化”是另一项能力，见[浏览器自动化](browser-automation.md)。

## 适合的任务

- 定期生成项目状态简报。
- 每天检查一个根对话并汇报重要变化。
- 周期性运行测试、整理日志或更新本地报告。
- 在应用下次启动时补做一次错过的检查。

不适合要求应用退出后仍准时运行、必须秒级触发、需要一次性提醒，或无法安全重复的高风险外部操作。

## 创建任务

1. 点击左侧栏“已安排”。
2. 点击“创建”或“创建任务”。
3. 填写任务名称和任务描述。
4. 选择运行目标、权限、频率和通知策略。
5. 核对摘要后保存。

任务描述应写成每次都可以独立理解的指令，例如：

> 检查当前项目的测试状态。不要安装依赖；运行已有单元测试，列出新增失败和可能原因。如果没有变化，明确报告无变化。

Scheduled Automation 当前不能附加文件、显式选择 Skill，也不能单独设置 temperature、max tokens 或 reasoning。需要 Skill 时，可以在任务描述中要求 Agent 使用当前可用的相应能力，但最终是否可用取决于运行时目录和配置。

## 选择运行目标

### 新聊天

每次 Run 创建一个新的根聊天。需要选择：

- 可选项目。
- 一个已启用模型。
- 权限模式。

适合每次结果相互独立的日报、扫描和报告。新聊天会保留在普通对话列表中；删除 Scheduled Automation 不会删除历史聊天。

### 现有聊天

每次 Run 在选定的活跃根聊天中追加一轮。归档对话、子 Agent 对话或不可写对话不能作为目标。

适合持续跟进同一个主题。它使用该对话当前绑定的项目和模型；如果目标被归档或删除，任务会进入“需要修复”。

## 设置频率

当前结构化频率包括：

- 每隔若干分钟、小时或天。
- 每天、工作日。
- 每周选择星期。
- 自定义每 N 小时、日、周、月或年，并选择分钟、时间、星期、日期和月份。

界面不接受自由文本 cron。也不支持一次性计划、结束日期或“运行 N 次后停止”。

创建或保存编辑时，任务会采用**当前电脑识别出的时区**。当前没有独立时区选择器；在另一时区的电脑上编辑并保存，后续触发时刻可能改变。涉及夏令时时，不存在的本地时刻会跳过，重复时刻不会执行两次。

## 选择权限

可以选择默认、完全或自定义权限，但完全/自定义必须先在“设置 → 常规”中启用。

保存时会冻结当时的有效权限：

- 未来修改全局自定义细项，不会自动改写旧任务。
- 关闭完全或自定义模式，会阻止对应任务的未来 Run 启动并使任务需要修复。
- 重新开启模式不会自动修复任务；需要编辑并保存任务。
- 要真正降低旧任务权限，必须编辑每条任务，或先关闭对应模式阻止执行。
- 自定义模式还会冻结符合条件的内置执行审批选项；它不会扩大文件、命令或第三方 Skill 权限。

默认权限的后台任务仍可能停在“等待批准”。系统会生成需要关注标记并尝试发送系统通知；应用重启后仍会等待同一个决定，不会默认批准。

## 通知策略

“新聊天”可以选择：

- 所有运行。
- 仅限未成功运行。

“现有聊天”可以选择：

- 重要更新。
- 仅限未成功运行。

需要审批、配置失效和部分重要结果也会形成需要关注标记。系统通知只是提醒，不是可靠交付保证：操作系统可能拒绝通知，当前没有应用内提醒兜底；极少数崩溃窗口还可能重复显示一次。普通任务的全局通知预设不会改写每项 Automation 保存的策略。

通知点击会尽量打开精确任务、Run 或对话消息。通知正文不会包含完整提示词、工具参数或凭据。

## 管理任务

“已安排”页面支持：

- 按全部、已开启、已暂停筛选和按名称搜索。
- 查看下次运行、健康状态和最近结果。
- 编辑、暂停、继续、立即运行或删除。
- 查看运行历史，按需打开对应聊天。
- 将需要关注项标记为已处理。

“立即运行”只是把一次运行加入队列；同一任务已经有活动 Run 时不会再启动第二次。

暂停只清除未来调度，**不会取消已经运行或等待审批的 Run**；暂停任务仍可以手动“立即运行”。当前 UI 没有独立的活动 Run 停止按钮。删除会停止未来调度、取消尚未真正开始的 Run，并请求取消活动 Run，但以前创建的聊天仍保留。

## 状态怎么理解

任务状态和健康状态是两件事：

- 已开启/已暂停：是否接受未来自动调度。
- 正常/需要修复：目标、项目、模型、权限或频率是否仍有效。

一次 Run 可能显示：已排队、正在启动、正在运行、等待批准、已完成、运行失败或已取消。运行历史还会标记触发来源：定时、手动或恢复。

“需要修复”时，打开任务，根据提示重新选择对话、项目、模型、权限或频率，再保存。资源恢复、权限重新开启或把需要关注项标记为已处理，都不会自动修复旧配置。

## 应用关闭和恢复

定时任务只在 Captain Who 及其本地运行组件工作时执行。应用退出、电脑关机或相关进程未运行时，不会有操作系统服务在后台唤醒任务。

下次启动时，离线期间错过的多个时刻会合并为**一次恢复 Run**，不会逐次补跑。调度器周期扫描，因此不承诺秒级准点。

## 安全建议

- 第一次先使用默认权限和“立即运行”验证提示词。
- 对可能写文件的任务使用版本控制，并把输出限制到明确路径。
- 不要用完全权限安排无法人工核对的支付、发布、删除或批量外部操作。
- 任务涉及第三方副作用时，写明幂等条件和重复运行处理方式。
- 定期检查“需要关注”和运行历史，不要只依赖系统通知。

## 当前限制

- 没有 cron、一次性计划、结束日期、附件或显式 Skill 选择。
- 没有单独停止活动 Run 的按钮，也没有独立的需要关注收件箱。
- 没有历史保留或清理策略的用户设置。
- 原生通知没有应用内提醒作为替代；界面未就绪时最多保留 32 个打开请求，溢出后丢弃最早请求。
