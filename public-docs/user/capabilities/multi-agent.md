# Multi-Agent

Multi-Agent 让一个根 Agent 组织多个子 Agent。每个子 Agent 有自己的任务、对话和模型运行，但仍属于同一棵协作树；根 Agent 负责分工、跟进、整合和向你交付结果。

## 什么时候适合使用

适合并行且边界清楚的工作，例如：

- 一个 Agent 阅读前端，一个阅读后端，最后交叉核对。
- 并行研究多个候选方案或资料来源。
- 实现、测试和文档分别审查。
- 让一个子 Agent 专注复现问题，另一个检查历史变更。

不适合把强依赖的连续小步骤全部拆开。子 Agent 之间的沟通和上下文复制也有成本；简单任务通常由一个 Agent 更快完成。

## 当前使用方式

目前没有面向用户的“创建子 Agent”按钮。你需要在根对话中明确要求根 Agent 分工，例如：

> 请把这个项目的评审拆成三个相互独立的子任务：前端交互、Rust 核心、测试与发布。并行完成后交叉检查，最后由你汇总。所有子任务先只读。

根 Agent 可以使用协作工具创建子 Agent、发送消息、安排后续任务、等待结果、查看树或中断后代。是否实际拆分仍取决于当前模型能否正确调用这些工具；可以在提示中要求它报告分工和每个子任务的状态。

## 创建子 Agent 模板

模板可以固定常用角色的名称、说明、指令和模型：

1. 先添加一个项目。
2. 打开“设置 → 子智能体”。
3. 选择项目，点击“新建模板”。
4. 填写名称、简短描述和完整指令。
5. 选择一个已启用模型并保存。

模板按项目隔离，不是全局模板。可以启停、编辑或删除；修改只影响未来创建的子 Agent，已经创建的节点保留当时快照。

## 在 Agent Center 中观察

当前根对话产生子 Agent 后，右侧栏会出现“子智能体”模块：

- “进行中”显示排队、运行和等待审批的子 Agent。
- “已结束”显示完成、失败、中断、结果未知、归档或停用状态。
- 打开一个子 Agent 可以查看它的只读对话和工具活动。
- 返回列表时会保留当前根任务的浏览位置。

子 Agent 对话是观察界面，不能直接输入消息、编辑历史或启动新运行。需要返工或补充时，在根对话中告诉根 Agent 对哪个子任务继续安排。

## 子 Agent 的审批

子 Agent 仍受文件、命令、Skill、MCP 和浏览器权限约束。需要用户决定的动作会路由到根任务的审批区域，并显示来源任务路径和工具名称。

审批前应核对：

- 这是哪个子 Agent 提出的动作。
- 它的目标是否在最初分工内。
- 是否与另一个子 Agent 同时修改同一文件或外部资源。

子 Agent 的权限不会比根任务更宽；后续任务还会根据祖先权限进一步收紧。

## 协作是如何组织的

当前结构是一棵树：每个子 Agent 只有一个直接父 Agent。发送消息只负责传递信息；真正安排下一次执行需要父 Agent 发出后续任务。子 Agent 完成一次运行后不会自动消失，后续仍可被再次唤醒。

每个 Agent 同时最多运行一个 Turn，交互式根 Agent、子 Agent 和 Scheduled Automation 共享并发容量。当前默认全局同时最多执行 4 个 Agent Turn，单棵树最多 64 个节点、深度最多 8；达到限制时任务会排队或被拒绝，而不是无限扩张。

## 实用提示

- 让每个子任务有明确输入、输出和禁止范围。
- 尽量避免两个子 Agent 同时写同一文件。
- 要求每个子 Agent 提供证据，而不是只返回“完成”。
- 最终结果由根 Agent 汇总，并要求它处理冲突和不一致。
- 涉及外部副作用时不要让多个子 Agent 重复提交同一动作。

## 当前限制

- 只支持树状协作，不支持任意依赖关系、条件分支或图形工作流。
- 用户不能直接编辑、启动或回复子 Agent 对话。
- Scheduled Automation 不能直接把目标设为子 Agent；它只能启动根任务，再由根 Agent 分工。
- Agent Center 只显示当前活动根对话的协作树，不跨多个根任务聚合。
- 进程崩溃后无法确认的外部副作用会保守标为结果未知，不会自动重放。
