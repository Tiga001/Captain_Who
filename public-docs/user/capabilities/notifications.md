# 系统通知

MyCopilot 可以在应用不处于桌面焦点时，用操作系统通知提醒任务完成、失败、取消或等待批准。通知只是提醒入口；任务、审批和 Automation Run 的真实状态仍以应用内记录为准。

## 配置普通任务通知

打开“设置 → 常规 → 通知”。“普通任务通知”提供四种模式：

- **从不**：普通任务不发送系统通知。
- **允许通知**：完成、失败、取消或等待批准时通知。
- **仅在必要时**：只通知失败、取消或等待批准。
- **自定义**：分别控制完成、失败、取消和等待批准。

这四种预设只控制普通任务的完成、失败、取消和等待批准事件，不改变 Automation 的触发条件。

## 全局展示设置

提示音和内容预览是普通任务与 Automation 共用的全局设置。你可以选择是否播放系统默认提示音，以及是否在通知中显示任务名称或任务描述的安全截取；关闭内容预览后，两类通知都只提示状态，不展示任务正文。

## Automation 通知

每项 Scheduled Automation 在创建或编辑时保存自己的通知触发策略；普通任务预设不会替代该策略。Automation 还会在配置失效或报告重要更新时按任务策略提醒，但展示时仍使用上述全局提示音和内容预览设置。

详细规则见[Scheduled Automation](automations.md)。

## 分组与点击

短时间内的多项状态可能合并为一条系统通知，并按“需要批准、配置失效、失败、重要更新、取消、完成”的优先级展示。点击后，应用会尽量打开对应对话、审批位置或 Automation Run；如果包含多项，则打开当时最高优先级的可导航项目。

应用界面尚未准备好时，最多保留 32 个待处理打开请求；极端连续点击超过上限时，最早的请求可能被丢弃。

## 交付边界

- 应用和 Core Server 必须运行；通知不是操作系统后台调度服务。
- 应用位于前台时，系统通知可能被抑制，避免重复打扰。
- 操作系统可能禁用、延迟或合并通知；当前没有应用内 Toast 或独立通知中心作为后备。
- 极小概率下，应用可能在“系统已经显示、确认尚未持久化”的窗口退出，重启后重复显示一次。
- 通知不能批准动作，也不能证明 Tool、任务或 Automation 已成功完成。

没有收到通知时，回到对应对话或 Scheduled 页面检查状态，不要根据通知缺失直接重复有副作用的操作。
