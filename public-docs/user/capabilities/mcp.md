# MCP

MCP（Model Context Protocol）让 MyCopilot 连接外部工具服务。当前用户可配置的 MCP Server 仅支持在本机启动的 **stdio 进程**；HTTP、OAuth 和远程 MCP URL 尚未开放。

## 使用前准备

你需要从 MCP Server 的发布方获得：

- 本机可执行文件的精确位置。
- 按顺序排列的启动参数。
- 一个有效的工作目录。
- 该程序的安装和安全来源说明。

当前配置不提供环境变量、专用密钥或请求头字段。不要把 Token、密码或 Cookie 放入命令参数或工作目录；这些字段会作为普通本地配置保存和展示。

## 添加 Server

1. 打开“设置 → MCP”。
2. 在“外部”区域点击“添加服务器”。
3. 填写名称。
4. 使用文件选择器选择可执行文件。
5. 将每个启动参数放在独立参数行中，保持发布方规定的顺序。
6. 选择工作目录。
7. 决定是否打开“允许自动执行工具”。关闭时，每次调用都会询问；打开时仍会经过身份和风险检查。
8. 点击“保存”。

新 Server 保存后默认停用，不会立即启动。

## 授权启动并启用

1. 在列表中打开 Server 详情。
2. 打开启用开关。
3. 首次启用会显示启动信息核对，确认这会在本机启动指定进程。
4. 授权后，MyCopilot 连接 Server 并发现工具。
5. 状态变为“已就绪”后，查看工具目录。

如果之后修改可执行文件、参数或工作目录，旧连接会停止，启动授权会失效；下次启用时需要重新核对。可执行文件或相关代码被替换后，也可能要求重新授权。

## 在任务中使用

启用后，MCP 工具会成为 Agent 的动态工具。可以在提示中说明期望使用哪个 Server，例如：

> 使用已启用的“数据库只读工具”查询本周新增记录，只返回汇总，不做写入。

“每次询问”模式会显示包含 Server、工具和参数摘要的审批卡。“允许自动执行工具”可以减少普通调用审批，但不会跳过 Server 身份、工具目录、参数、并发和敏感风险检查。

调用一旦可能已经发给外部进程，超时、取消或连接断开时可能出现“结果未知”。对于写入、发消息或支付等动作，不要自动重复调用，先检查外部系统。

## 管理和排错

详情页会显示连接状态、工具数量、启动配置和可选技术详情。常见状态：

- 正在启动/连接/发现工具：等待协商完成。
- 已就绪：完整工具目录可用。
- 能力降级/需要处理：目录不完整或状态异常，不能假定缺失工具不存在。
- 错误/等待重连：核对程序、参数和工作目录，再点“重试连接”。

只有完整且通过校验的工具目录才会交给 Agent。刷新目录不能修复 Server 自身的错误。

停用会阻止新调用并关闭连接。删除只移除 MyCopilot 配置，不会卸载本地程序；活动调用的最终结果可能仍无法确认。

## 受管 MCP 能力与外部 Server

“设置 → MCP”当前只管理用户添加的本地 stdio Server。浏览器自动化在底层使用应用受管的 MCP 通道，但配置入口已经独立到“设置 → 浏览器”；它不填写可执行文件或参数，也不属于你的外部 Server 列表。使用方法见[浏览器自动化](browser-automation.md)。

## 当前限制

- 外部 Server 仅支持本地 stdio。
- MCP Resources、Prompts、Sampling、Elicitation、Tasks 和 Apps 没有进入 Agent 用户路径；当前主要使用 Tool。
- 没有环境变量、专用密钥字段、OAuth 或远程连接配置。
- Windows 上不能把外部 Server 视为具有完整进程树隔离。
- Server 提供的名称、描述和“只读”标记都是不可信提示，不能自行降低审批。
