# 组织

组织把多个独立智能体对话连接成一个邮件协作网络。成员共享组织背景，各自保存职责、模型和权限，并根据任务向其他成员发信。

**版本范围：本页描述截至 2026-10-04 已核验的当前开发版本，不代表所有已发布安装包都包含这些能力。** 请先核对应用版本和实际入口；对应版本的变更以[发行说明](../../releases/release-notes/README.md)为准。

## 从工作流到组织

当前开发版本已移除旧的工作流功能，改用组织。组织没有固定执行连线、输入/输出逻辑门、条件分支或批次门槛。画布位置用于整理成员与部门，不能决定执行先后；看板上的短暂连线只表示实际邮件传输。

旧工作流格式不会自动转换成组织。若旧模板或暂存内容显示不可用，应重新创建组织模板；不要把改名理解为原有工作流可以直接继续执行。

## 组织、Multi-Agent 与定时任务

| 需要                                                   | 适合的能力                             |
| ------------------------------------------------------ | -------------------------------------- |
| 一个主任务临时拆分调查、实现或审查，由根 Agent 汇总    | [Multi-Agent](multi-agent.md)          |
| 多个独立对话长期保留各自职责，成员间按需交换任务和结果 | 组织                                   |
| 同一任务按时间重复启动                                 | [Scheduled Automation](automations.md) |

组织成员都是可以直接打开和交互的独立根对话，不是根 Agent 树中的只读子对话。成员可以按已有 Multi-Agent 能力另行委派子任务，但子 Agent 不会因此取得组织成员身份或组织邮箱。组织也不提供定时计划，不能代替 Scheduled Automation。

## 模板与已激活组织

- **组织模板**：在“设置 → 组织”中管理的可复用成员配置；保存模板不会创建对话或启动模型。
- **已激活组织**：从模板复制后独立保存的成员、部门、背景、模型、权限和对话绑定。
- **组织看板**：观察成员活动、审批、邮箱和最近邮件传输，不是执行流程设计器。

模板只有通过当前配置校验后才可用于新建组织，没有单独的模板启用开关。模板修改或删除不会更新、停用或删除已经激活的组织；需要调整已有组织时，打开该组织的“配置”。保存已有组织会保留原来的启用或停用状态。

组织不属于某一个项目。新建时的“所属项目”只决定自动创建的对话放在哪里，绑定的已有对话仍保留原项目。一个对话不能重复分配给不同成员或不同组织；子 Agent 对话不能绑定为组织成员。

## 创建与开始工作

1. 从左侧栏打开“组织”，在右侧栏组织首页选择“管理组织模板”。也可以直接进入“设置 → 组织”。
2. 点击“新建组织模板”，填写名称和组织公共背景，在“组织设计”中添加智能体。
3. 为每位成员设置唯一名称、可用模型、权限，以及“这个节点会收到什么”“这个节点需要做什么”“这个节点需要交付什么”。保存组织模板。
4. 返回组织首页，点击“激活新组织”，选择模板，检查名称、颜色和可选的所属项目。需要复用已有对话时，在成员配置中“绑定对话”，也可以拖入对话。
5. 点击“激活”。未绑定的成员会自动获得新对话；没有待处理邮件时，成员保持空闲，不会仅因激活就调用模型。
6. 打开“组织看板”，双击成员进入其对话，发送具体目标与验收条件。成员可按职责向其他成员发信推进工作。

成员名称在整个组织内必须唯一，大小写和首尾空格不能用来区分。模型不可用时，启用操作会列出相关模型和成员；先修复模型设置，或在组织配置中换用可用模型。

完整示例见[创建并运行一个组织](../tutorials/create-an-organization.md)。

## 邮件怎样推进任务

这里的“邮件”是组织内部的协作消息，不是电子邮件，也不会直接发送到外部邮箱。

- 空闲成员按到达顺序接手一封待处理邮件，开始一个普通对话回合。
- 成员正在工作时，新邮件留在收件箱，不会强行插入当前工作。成员可以先查询，再主动领取本轮要处理的其他邮件。
- 查看邮件不等于领取。正常结束回合时，本轮已正式接收且仍在处理中的邮件会自动标为已处理；需要先结清某封邮件再继续工作时，成员也可以提前完成它。
- 回到空闲后若仍有待处理邮件，会继续按顺序接手；没有待办时保持空闲，后续新邮件可以再次唤醒。
- 发件人只能撤回尚未被领取的邮件。已领取、已处理的内容不能通过撤回收回。

“已处理”只表示邮件处理回合已结束，不保证交付正确。应继续检查实际回复、文件、测试和来源。成员没有新事实、新成果或必要问题时无需反复回复“收到”，也不应通过重复查邮箱来空等同事。

### 发送、回复、查询与领取

你可以在成员对话里要求它“把结论和来源发给审阅员”“查看尚未处理的组织邮件”或“回复这封来信中的问题”。成员按组织内唯一姓名寻址，也可以直接回复自己的来信；一次发送给多人时，每位收件人都有独立邮件和处理状态。

| 操作            | 作用与边界                                                                   |
| --------------- | ---------------------------------------------------------------------------- |
| 发信或回复      | 把任务、结果或必要问题交给成员；不能伪造发件人，也不直接控制对方当前运行     |
| 查收件箱/发件箱 | 查看自己的邮件与状态；查询待办会提供正文，但不会领取或完成                   |
| 领取            | 只有决定本轮处理某封待处理邮件时才使用；已经正式交付本轮的来信不需重复领取   |
| 完成            | 可在本轮提前结清已接收邮件；正常结束也会自动结清本轮已经正式交付的处理中邮件 |
| 撤回            | 只对自己发出且尚未被领取的邮件生效；多人收件时应分别核对结果                 |

不要为了“保证收到”而重复发送同一任务。没有新事实、新问题或必要交接的确认来回会增加成本，不能代替推进工作。

## 部门、职级与管理身份

**部门层级约束人员管理范围，不限制邮件通信。** 普通成员可以给其他部门或更高职级成员发信，不需要先沿层级逐级转交；收到上级邮件也不会自动获得上级的工具权限。

组织设计可添加部门框，并通过完整嵌套形成下级部门。将成员完整放入部门框即可设置归属；部门框不能部分交叠。移动部门会带着内部成员和下级部门一起移动；删除部门框保留里面的成员与下级部门，并重新计算归属。

成员的“职级”页包含 1–99 的职级和管理身份：

- **普通成员**：可以协作通信，没有人员管理能力。
- **组织管理员**：可以管理全组织中职级严格低于自己的成员。
- **部门管理员**：可以管理本部门及下级部门中职级严格低于自己的成员。

职级数字越大越高，但高职级本身不会自动获得管理权。管理员不能修改自己，不能借调整职级或移动部门管理同级或更高职级成员；部门管理员不能任命组织管理员。

管理员可通过对话按权限添加、修改或移除成员与部门。删除部门的人员管理操作只接受空部门，应先移走直属成员和下级部门。新成员尚未收到邮件时不会运行；移除成员会撤销其组织身份，但保留聊天历史。模型执行人员管理时不能把其他成员的工具权限提高到自己本轮实际权限之上。

### 一个分工例子

组织管理员“负责人”为职级 3；“研究部”的部门管理员“研究员”为职级 2；“评审部”的普通成员“审阅员”为职级 1。负责人可在权限范围内管理后两人；研究员可以管理研究部及其下级部门中职级 1 的成员，但不能管理评审部的审阅员。研究员和审阅员仍可直接互发邮件，不需要负责人代转。

你可以让负责人“把研究员的交付要求补充为每条结论附来源”，也可以让研究员“在研究部新增一名资料核对员，核对引用与原文是否一致”。新增成员默认是普通成员、职级 1，继承调用者所在部门和本轮可用配置；仍要核对实际变更回执，不把请求文字当成修改成功。

同一上级下的部门名称必须唯一，不同层级可通过完整部门路径区分。管理操作指向部门时应说明完整路径，例如“研究部/资料组”；不要在单个部门名称里直接写斜杠模拟层级。

## 看板与日常管理

- 悬停成员查看职级、模型、权限和任务；双击打开真实对话，在对话中使用邮箱工具查看邮件。
- 邮件显示待处理、处理中、已处理、已停止、失败、已撤回六种状态，具体含义见[状态说明](../reference/statuses.md)。
- 短暂连线来自真实发送或撤回事件，消失不表示丢信；重新打开看板不会重播全部历史。
- “已连续运行”表示最近一段实际连续活动时长，多人并行不会相加，也不是从创建组织开始计时。
- 在“配置”中可在线修改成员、部门、职责和默认模型/权限。只调整职责、职级或布局，不会覆盖你在成员对话中选择的模型与权限。
- 明确修改成员默认模型或权限会影响后续输入配置，已经运行的回合继续使用原有配置。

## 停用、停止与归档

**停用组织**会阻止新的组织邮件发送与投递，保留对话、绑定和未处理邮件，不会停止已经运行的任务。若需要停止某位成员当前工作，应打开该成员对话并点击停止。

**手动停止成员对话**后，后续邮件仍保留在收件箱，不会立即自动唤醒。向该对话手动发送新消息可恢复正常收信处理；仅查看邮箱不会恢复。

启用组织中绑定的对话不能归档，应先停用组织。归档后重新启用前，需要恢复或重新分配有效对话，并通过模型、成员配置和颜色检查。移除成员或绑定对话不会删除其他成员，也不等于关闭整个组织。

## 权限与数据边界

组织成员仍受各自对话的项目、模型、权限和审批约束。组织管理员身份只用于组织人员配置，不是文件、命令、浏览器或外部服务的额外授权。成员邮件是协作资料，不能冒充你的批准。

组织背景、职责和邮件可能进入对应成员的模型请求。成员使用不同模型服务时，同一项任务资料可能发往多个 Provider；不要把不应共享的秘密放入公共背景或邮件。详细说明见[数据与权限](../../security/data-and-permissions.md)。
