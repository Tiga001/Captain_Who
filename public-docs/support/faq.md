# 常见问答

## Captain Who 能离线使用吗？

界面、项目历史和许多本地 Tool 是本地运行的，但语言模型请求通常需要连接你配置的 Provider。联网搜索、网页访问、图片生成、GitHub Skill 安装以及会联网的 MCP Server 也需要网络。

## 必须使用某一家模型服务吗？

不必。1.0.7 支持 OpenAI-compatible、Anthropic-compatible、DeepSeek V4 Chat、Moonshot 和智谱对应的适配方式，但具体端点必须满足协议要求。兼容网关需要自行验证；型号与参数见[连接模型 Provider](../integrations/model-provider-integration.md)。Kimi K3.1、智谱 GLM-5.3 和厂商型号选择界面已随 [1.0.7](../releases/release-notes/1-0-7.md) 发布，1.0.6 用户需先升级。

## 智谱 Coding Plan 能直接用于智谱配置吗？

当前专用配置面向国内标准 API，固定使用 `open.bigmodel.cn` 的标准接口，请填写标准 API Key，按量计费；它不接入 Coding Plan 套餐或海外 Z.AI。该配置不会检查或转换你的套餐额度。详见[智谱 GLM-5.3 配置](../integrations/model-provider-integration.md#智谱-glm-53-配置)。

## Captain Who 会自动收费吗？

应用显示的费用是根据用户填写的每千 Token 单价计算的本地估算，不是服务商账单。模型、搜索、图片生成和第三方工具是否收费，由相应服务商决定。

## 数据都只保存在本机吗？

项目、对话、文件、Agent 轨迹、密钥和本机 Token 活动主要保存在本机，不会同步到 Captain Who 的账户与许可服务。使用网站或云端账户时，账户服务会处理账户、个人资料、认证/会话、许可及必要的服务安全记录；1.0.7 的内置本地账户不访问云端身份与许可服务。模型、搜索、图片、网页和 MCP 请求仍会发送到你选择的服务或本地进程。参见[数据与权限](../security/data-and-permissions.md)。

## 为什么需要登录和软件许可？

登录状态和软件许可决定能否启动新的 Agent 回合，不会因此上传本机项目、对话、文件、模型设置或 Token 活动。云端账户无法完成许可校验时，可在应用中重新验证或打开官方账户页面管理许可；1.0.7 的内置本地账户登录后直接具有本地使用资格。它不是独立数据空间，也不提供模型额度，步骤和版本范围见[账户与软件许可](../user/getting-started/account-and-license.md)。

## Token 保存在哪里？

模型 Token、Tavily Key 和图片生成 API Key 与 SQLite 配置分离：SQLite 只保存不透明引用和状态。具备稳定签名身份的发行构建使用操作系统凭据存储；未签名 macOS 开发构建使用数据目录内权限收紧的私有文件。应用不会在设置页读回已有密钥。

## 为什么 Agent 会请求批准？

FileChange、命令、外部 MCP 调用、Skill Script 或浏览器敏感动作可能产生副作用。批准会绑定到具体动作或当前 Run 的明确记忆范围，而不是给模型永久授权。应核对目标、Diff、参数和影响后再决定。

## Skill 和 MCP 有什么区别？

Skill 主要告诉 Agent“怎样做”；MCP Server 主要提供“可以调用什么工具”。Skill 不会因为来源可信而自动获得文件、命令或网络权限。

## 工作流在哪里？组织和子 Agent 有什么区别？

1.0.7 已移除旧工作流，改用[组织](../user/capabilities/organizations.md)。组织成员是共享背景、按需互相发信的独立对话，你可以直接与每位成员交互；Multi-Agent 则由根 Agent 把任务分给树状子 Agent。组织没有固定连线或逻辑门，旧工作流格式不会自动转换。1.0.6 不包含这一组织能力。

## 为什么激活组织后没有开始工作？

激活只保存组织并绑定对话；空邮箱不会启动模型。打开组织看板，双击成员进入对话并给出目标，成员再按职责协作。已有待处理邮件却没运行时，检查组织开关、手动停止状态、审批、模型配置与执行容量。

## 修改模板或停用组织会影响现有任务吗？

已激活组织拥有独立配置，模板修改或删除不会改变它。停用组织阻止新的组织通信与投递，但不会停止已有运行；要停止当前工作，需进入相应成员对话操作。保存停用组织的配置不会自动启用。

## Scheduled Automation 会在应用退出后继续运行吗？

不会。它不是操作系统后台服务，只有 Captain Who 与 Core Server 运行时才会启动任务。离线期间错过的多个计划时间会在下次启动合并为一次恢复运行，而不是逐次补跑。

## 暂停 Automation 会停止当前 Run 吗？

不会。暂停只阻止未来计划；当前界面也没有单独停止活动 Automation Run 的按钮。删除任务会进入取消与清理流程，但已经发生的外部副作用无法撤销。

## 移除项目会删除项目文件吗？

不会修改项目目录中的文件，但会永久移除 Captain Who 中该项目的本地对话、消息和附件记录。操作前应确认不再需要这些历史。

## 是否支持自动更新？

正式签名 macOS 发行版内置应用内自动更新机制。完整初始化后，只有在可访问的官方更新源提供新版本时，应用才会显示下载入口；由你选择开始下载，下载、完整性校验和原生准备完成后，应用会退出并重新启动以安装。它不会在你没有开始下载时自动下载、静默替换版本，也不提供自动回滚。其他平台和开发构建不应据此推断具备相同更新能力。更新源不可用、替换安装包或更新失败时，请阅读[升级指南](../releases/upgrade-guide.md)。

## 浏览器自动化会使用我的系统浏览器吗？

不会。Agent 自动化只控制应用管理的浏览器环境，不连接任意外部调试端点。它与手动浏览界面也有独立的授权边界。

## 浏览器下载保存在哪里？

保存在“设置 → 浏览器”选择的系统默认或自定义下载目录。手动下载可以逐次询问位置，Agent 下载直接使用配置目录；下载中心和历史页不向模型暴露绝对路径。

## 没有系统通知是否表示任务没运行？

不是。通知可能因应用前台、系统权限、合并或交付失败而不可见。应回到对应对话或 Scheduled 页面查看真实状态；通知也不能代替审批。
