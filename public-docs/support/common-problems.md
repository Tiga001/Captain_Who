# 常见问题排查

## 应用一直停在启动界面

完全退出后重新启动一次，并保留首次错误。若仍失败，不要删除应用数据目录或手工修改数据库；记录应用版本、系统版本和启动阶段提示，用于继续定位。

## 模型请求失败

依次检查：

1. API URL 是否为完整的 `http` 或 `https` 地址；
2. Token 与 URL 是否来自同一个 Provider；
3. 模型标识是否与服务商实际名称一致；
4. 模型是否已启用；
5. 所选兼容配置是否与服务商协议一致；
6. 网络、账户余额、速率限制和服务状态。

配置完整不代表远端已经验证。不要把完整 Token 放进截图或任何要共享的排查材料。

## Agent 一直等待批准

打开对应对话，查看等待中的具体动作。批准或拒绝后，Agent 会尝试继续同一个 Run。通知只负责提醒，不能替代批准；如果状态仍未更新，刷新对话后再检查，不要新建重复任务。

## MCP Server 无法启用

- 当前只支持本机 stdio，不接受 HTTP URL。
- 确认可执行文件与工作目录仍存在。
- 保存配置后还需单独启用，并在确认框中授权启动。
- 程序、参数、工作目录或代码入口变化会使旧授权失效。
- Catalog 不完整时，检查 Server 的 Tool 名称和 schema，而不是开启自动执行。

如果调用结果显示未知，不要自动重试；调用可能已经到达 Server。

## Skill 没有出现或未触发

- Workspace Skill 必须位于 `.agents/skills/<name>/SKILL.md`，并使用精确大小写。
- 检查 YAML front matter 中的 `name` 与 `description`。
- 确认 Skill 已启用，且当前任务打开了正确项目。
- 修改后新建任务测试；已经开始的 Run 会继续使用冻结版本。
- 描述过宽会误触发，过窄则可能不触发。

## 浏览器自动化不可用

确认 MCP 设置中的内置浏览器自动化能力已允许，并在当前任务中批准能力激活。网页权限、敏感站点、文件上传、下载和网络目标还可能需要单独批准或被安全策略拒绝。

站点需要摄像头、麦克风、定位或网页通知时可能无法正常工作，因为受管浏览器默认拒绝这些网页权限。

## Scheduled Automation 没有运行

1. 确认应用在计划时间运行。
2. 确认任务为 Active，健康状态不是 Blocked。
3. 检查模型、项目、目标对话和权限模式仍然可用。
4. 查看 Run 是否处于排队、运行或等待批准状态。
5. 修复 Blocked 配置后重新保存任务；资源恢复不会自动解除 Blocked。

调度不是秒级定时器。已有活动 Run 时，同一任务不会并行启动另一个 Run。

## 原生通知没有出现

检查操作系统是否允许 MyCopilot 发送通知，再到 Scheduled 页面查看真实 Run 和 attention。通知不是任务执行成功的证明；当前没有界面 Toast 作为系统通知的后备。极少数情况下，应用在“通知已显示、确认尚未保存”之间退出，重启后可能重复一次。

## Office、PDF 或图片任务失败

- 确认文件格式受支持，扫描 PDF 是否含文本层。
- 确认输出目录可写，输入文件没有被其他程序锁定。
- 图片生成需要完整、已启用的 Provider 配置；本地“就绪”不代表远端模型和密钥已验证。
- 远端图片请求超时后可能已经计费或生成，不要直接重复提交。

仍无法解决时，按[诊断信息与日志](diagnostics-and-logs.md)准备脱敏的最小复现材料。
